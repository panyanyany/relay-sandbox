## 讨论深度与行为范围

采用架构层级：涉及对话入口、执行职责、审查触发、生命周期及已有前端兼容。

1. 系统对象：中转沙箱独立终端及 Webcoding 接入。
2. 输入：用户启动终端、发送多轮消息、取消与退出；具体触发规则待确认。
3. 协作者：沙箱开发 Agent、宿主控制程序、可选宿主审查 AI；职责待确认。
4. 可观察结果：由谁直接回复、何时显示独立审查结果，待确认。
5. 失败可见性：开发失败、审查不可用和证据缺失的提示与继续规则，待确认。
6. 不得采用的捷径：只更换界面名称而仍让宿主 AI 转述全部开发对话；把回复结束视为审计完成；把未观察到异常描述为已验证安全。

## 已确认决定

### D1：终端直接与沙箱开发 AI 对话

- 分类：issue-local / pending issue package；架构方向，具体边界继续对齐。
- 用户选择：Q1 选项 1。
- 行为：用户消息直接交给容器内选定的开发 Agent，开发 Agent 的回复直接呈现，不经常驻宿主协调 AI 转述。
- 宿主职责：程序管理环境和采集日志，需要审查时单独调用审查 AI；触发时机、失败处理和审查配置待确认。
- 继承约束：沙箱开发 Agent 可配置，不限定为 Codex；已有 MCP 宿主工作流的兼容范围另行确认。
- 验收方向：多轮消息确实进入同一沙箱开发会话；日常开发对话不产生宿主协调模型调用；审查输出与开发回复明确区分。
- 架构来源处置：A1 对终端对话职责为 supersede（目标方向已确认、尚未实施）；对已有 MCP 宿主模式的处置仍待确认。当前实现文档继续描述现状，实施时再更新。

### D2：明确结束工作时统一审查

- 分类：issue-local / pending issue package。
- 用户选择：Q2 选项 2。
- 行为：多轮开发期间持续采集日志，不在每轮回复后自动调用审查 AI；用户明确结束本次工作时统一审查。
- 权衡：减少逐轮审查等待和模型调用，异常可能到收尾时才被 AI 判断。
- 验收方向：普通回复完成不触发审查；明确收尾操作触发独立审查，并与开发回复区分。
- 尚未确认：具体命令、审查失败处理、异常退出后的补审、审查模型和证据范围。

### D3：宿主程序控制收尾与独立审查

- 分类：issue-local / pending issue package；架构职责边界。
- 用户确认：接受上一轮提出的程序控制流程并继续对齐。
- 行为：宿主程序转发用户与沙箱开发 Agent 的多轮消息，识别用户明确收尾操作，暂停本次开发、保存代码差异与审计证据，再调用宿主侧独立审查 AI，展示结论并保存结构化结果。
- 触发边界：沙箱开发 Agent 的普通完成回复不触发统一审查；不依赖其主动通知，不以其自报状态证明审查完成。
- 配置边界：审查模型、地址和凭据可独立配置，审查凭据不提供给沙箱开发 Agent。
- 宿主角色：普通程序控制收尾，不维持常驻的宿主协调 AI。
- 命令名称：`/finish` 作为收尾入口的提议名称；最终名称可按已有命令冲突检查确定，不因此改变触发语义。
- 验收方向：沙箱不发送审查请求也能收尾；普通消息不误触发；审查读取本次固定证据；开发回复与审查结果明确区分；开发环境不能取得审查凭据。
- 来源处置：A1 在终端职责上 supersede，原 MCP 模式兼容范围仍待确认；当前实现尚未变更。

### D4：审查失败保留待审状态，允许退出和补审

- 分类：issue-local / pending issue package。
- 用户选择：审查失败问题选项 1。
- 行为：审查超时、凭据失效或返回结果不能解析时，保留开发成果及已保存证据，明确标记“审查未完成”，允许用户退出并稍后重试审查。
- 结果边界：失败不能记为审查通过，不能把开发成功等同于审查成功；需要区分可用的失败原因。
- 数据边界：直接挂载已生效的修改不会因审查失败而自动撤销；不因审查失败删除环境或证据。
- 验收方向：模拟超时、鉴权失败、非法结构化输出，均显示未完成；退出后仍可对原证据补审，不要求重新执行开发。

### D5：异常中断不自动调用审查 AI

- 分类：issue-local / pending issue package。
- 用户选择：异常中断问题选项 1。
- 行为：直接关闭终端或容器意外退出时，保留可用现场和证据，标记未审查；下次进入时提醒，由用户选择继续开发或补审。
- 调用边界：不因终端断开或容器退出擅自发起后台收费审查。
- 证据边界：意外退出只能保留已经持久化或仍可恢复的内容；证据缺失须提示，不保证强杀或宿主故障后完整恢复。
- 验收方向：普通异常断开不产生审查模型请求；再次进入展示未审提醒；继续开发与补审各有明确入口，不误标通过。

### D6：默认审查代码改动和运行行为

- 分类：issue-local / pending issue package。
- 用户选择：审查范围问题选项 1。
- 行为：明确收尾后，默认同时审查本次代码改动及运行期证据，分别展示代码风险结论、敏感资源访问与可疑通信线索、审计覆盖缺口。
- 配置继承：用户已有的关闭代码 AI 审核配置继续生效，不借本次终端改造重新启用；其他既有交付检查按冻结策略执行。
- 语义继承：运行期线索不直接等同于恶意，不把审计无记录视为安全，也不把独立运行风险提醒混入代码 verdict。
- 验收方向：同一报告区分代码与运行行为；关闭代码审核时不执行代码 AI 审核；部分证据缺失明确提示，不误报完整安全结论。

### D7：终端与 Webcoding 同步直连，保留 MCP 委派模式

- 分类：issue-local / pending issue package；入口兼容与架构职责。
- 用户选择：Webcoding 范围问题选项 1。
- 行为：独立终端与 Webcoding 的“中转沙箱”均直接与沙箱开发 Agent 对话；网页提供明确的“结束并审查”操作，执行相同收尾及独立审查规则。
- 兼容范围：现有供外部 AI 调用的 MCP 委派工作流保留，不随新终端的职责调整而废弃或静默改为直连。
- 来源处置：A1 对终端与 Webcoding 对话职责为 supersede；对外部 MCP 宿主委派模式为 inherit。历史宿主协调会话的具体续接兼容方法留给实现核对，不能冒充沙箱直连会话或混用线程身份。
- 验收方向：同一需求在终端和网页均直接进入沙箱 Agent，不产生常驻宿主协调模型调用；网页显式收尾才触发审查；既有 MCP 派发、审核、上报流程回归通过。

### D8：普通退出与收尾审查分开

- 分类：issue-local / pending issue package。
- 用户选择：退出行为问题选项 1。
- 行为：`/exit` 或关闭网页只离开并保留会话，不自动调用审查 AI；只有用户明确执行“结束并审查”才触发统一审查。
- 展示：存在尚未审查的工作时保留待审提示，下次进入可继续开发或补审。正常离开不因此误标为执行故障。
- 生命周期边界：保留会话不等于要求后台开发继续运行；离开时正在执行的轮次及服务如何处理仍待确认。
- 验收方向：普通退出、关闭网页无审查模型请求；再进入可找到原会话；显式收尾操作与普通退出明确区分。

### D9：原会话可继续开发，审查结论绑定证据版本

- 分类：issue-local / pending issue package。
- 用户选择：审查后继续开发问题选项 1。
- 行为：审查完成不永久关闭会话，用户可在原沙箱开发会话继续工作；新工作重新标记待审，历史报告保留。
- 结果边界：报告仅覆盖其固定的代码与日志版本，不能自动视为覆盖后续修改或行为。再次明确收尾时审查新的工作。
- 失败补审：沿用 D4，对原证据的补审不要求重跑开发；继续开发后的当前状态不得由旧证据补审冒充已审查。
- 验收方向：完成审查后继续开发仍保留对话连续性；待审状态更新；旧报告可追溯到原证据；新旧结论不混用。

### D10：离开后本轮后台继续，不新增专用守护进程

- 分类：issue-local / pending issue package；生命周期与部署约束。
- 用户选择：离开时执行行为选项 1，补充“不需要特别安排一个守护进程”。
- 行为：终端或网页断开后，已经开始的本轮开发及审计采集继续；重新进入可查看进度和结果。不因断开自动调用收尾审查，不自动增加下一轮需求。
- 部署边界：不新增专用常驻 daemon、独立 PM2 应用或系统服务；使用任务自身的后台执行进程和现有运行基础设施。后台任务进程不等同于额外常驻守护服务。
- 当前事实：`src/tasks/dispatch.ts` 已使用 detached 子进程、日志文件和 unref 派发后台任务；这仅证明已有可复用机制，不代表当前终端已支持断线续跑。
- 可靠性边界：不承诺宿主重启、任务进程崩溃后自动拉起；沿用 D5 保留可用证据并提示待处理。容器实际退出仍属于中断，不因前端断开应继续而假报仍运行。
- 验收方向：关闭前端后本轮可完成、日志持续落盘，重连能读取结果；不注册新的守护服务；显式停止与前端离开不是同一动作。
- 对 D8 的补充：离开时活动轮次继续，本轮完成后等待新的用户输入。

### D11：独立终端呈现沙箱 Agent 原生交互界面

- 分类：issue-local / pending issue package；终端交互契约。
- 用户选择：终端界面问题选项 1。
- 行为：独立终端呈现容器内选定开发 Agent 的原生交互界面，保留其终端输入输出、快捷键与窗口变化；不将其替换为中转沙箱自绘聊天界面。
- 接入边界：终端透传与断线后的会话存活分开验证；仅打开 Docker 交互终端不作为已满足 D10 的证据。
- 兼容约束：中转沙箱收尾和退出操作不得无差别拦截原生 Agent 同名斜杠命令；具体入口已由 D13 确认。
- 验收方向：至少覆盖所支持 Agent 的原生界面显示、键盘交互、窗口缩放、断开后本轮继续与重新连接。
- 未定范围：Webcoding 界面在当时待定，后续由 D12 确认为结构化聊天。

### D12：Webcoding 保留结构化聊天界面

- 分类：issue-local / pending issue package；前端交互及协议边界。
- 用户选择：Webcoding 界面问题选项 1。
- 行为：Webcoding 继续显示现有聊天消息、工具调用及明确的审查操作，消息直接发送给沙箱开发 Agent；不嵌入原生终端替代聊天界面。
- 与 D11 的关系：独立终端呈现原生交互界面，网页通过结构化消息适配同类沙箱开发会话；两端不要求相同界面，不引入宿主 AI 转述。
- 验收方向：网页消息及工具结果来自容器内实际 Agent，审查作为独立操作和结果展示；终端原生交互能力不因网页适配被取消。
- 尚未承诺：两端是否同时操控同一原生会话、跨模式迁移及多写入者并发控制，后续单独确认，不能由本决定推断。

### D13：使用独立 review 子命令审查会话

- 分类：issue-local / pending issue package；公开 CLI 入口。
- 用户提出并确认方向：`relay-sandbox` 类似 Codex 进入原生开发终端，`relay-sandbox review <session-id>` 对指定会话发起独立审查。
- 行为：收尾审查入口由宿主 CLI 子命令提供；不要求原生 Agent 主动发消息，不拦截原生斜杠命令，不以新增专用快捷键或退出后外层菜单作为必需入口。
- 网页对应：沿用 D7、D12 的明确审查操作，与 CLI 使用同一审查语义。
- 结果边界：沿用 D4、D6、D9，保存结构化结果，失败标记未完成并可补审，历史报告只覆盖其固定证据；审查后可以继续原会话。
- 公开接口兼容：当前 `src/cli/main.ts` 已有 `review <id>` 任务审核入口，带审核输入参数；新会话审查不能静默误解释旧任务调用。后续保留旧参数调用兼容，并明确对象类型与错误提示；命令内部路由属于实现工作。
- 验收方向：已知会话 ID 可从另一终端发起审查；不存在的 ID 明确报错；不启动常驻宿主协调 AI；Agent 原生输入不被截获；既有 CLI 审核入口回归验证。
- 尚未确定：目标会话正在执行时是等待本轮完成还是主动停止后审查。

### D14：忙碌会话拒绝审查，立即报错退出

- 分类：issue-local / pending issue package；并发及错误语义。
- 用户决定：目标会话正在开发时，直接退出并提示错误。
- 行为：`relay-sandbox review <session-id>` 遇到仍在执行的会话，立即返回明确错误和非零退出码，不等待、不请求停止开发、不调用审查模型；网页相应审查操作采用相同忙碌拒绝规则。
- 提示方向：说明目标会话仍在执行，请待其空闲后重试；不把此预期拒绝误记为审查已通过或已生成新报告。
- 竞态边界：空闲检查与固定证据期间必须互斥新的开发执行，不能检查为空闲后允许并发写入而仍宣称审查同一固定版本。
- 验收方向：运行中立即拒绝且开发继续；零审查模型调用；状态转为空闲后可重试；审查与新开发并发请求不能同时进入证据固定阶段。
- 对 D13 的补充：审查不承担等待或中断当前轮的职责。

## 调用方式澄清（事实与方案说明，非新增用户决定）

- 当前 Webcoding 适配器调用本项目 CLI 的 `chat --json --input-json`，再由现有终端实现启动宿主 Codex；没有为网页另写一套直连模型 HTTP 接口。
- D1、D7 目标是移除该开发对话中的宿主协调 AI，网页通过本项目 CLI 调用容器内 Agent，独立终端通过原生交互界面连接容器内 Agent。
- 同一个 Agent 命令行程序可有原生交互和结构化输出模式；项目已有 Codex `exec --json`、OpenCode `run --format json` 适配。两种交互模式不等于两套独立模型接入。
- 两种模式是否能恢复同一原生对话需要按 Agent 实测；尚未由用户决定要求或排除跨入口续接，不因询问而推断另建网页专用模型通道。

### D15：统一会话身份，终端与网页打开同一开发会话

- 分类：issue-local / pending issue package；会话模型及跨入口契约。
- 用户决定：交互通道统一时，从终端切换到网页应只是打开同一个会话 ID。
- 行为：独立终端和 Webcoding 作为同一沙箱开发会话的不同呈现入口，通过同一中转沙箱会话 ID 定位同一底层 Agent 会话、工作环境、执行状态及审查记录；支持跨入口继续同一段开发对话。
