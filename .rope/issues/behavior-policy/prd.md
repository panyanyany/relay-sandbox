# 行为边界、授权例外与可选诱饵审计

状态：原执行包实施、双审及 verify 已完成，E1–E6 已记录通过证据。后续维护修复见 [维护性修复](../../../devdocs/maintenance.md)；本包不代表全项目稳定化验收完成。

## 原始问题（实施前）

实施前，网络默认禁止任务外部内网，与已确认的新规则不符。尚无可信宿主资源授权层、直接目录共享或产品级诱饵通信检测。现有敏感路径记录不能区分正常安装与恶意行为，也不能证明数据是否发送到外部。

## 方案

分离强制隔离、可信授权、可选通信观察和事后风险判断。采用已有 Docker、归档和审查机制，增加小模块，不把业务集中到 CLI/MCP 或任务入口。任务级代理优先复用 mitmproxy，固定版本和镜像；仅为明确启用的审计功能启动，不改宿主全局代理、证书或防火墙。

## Contract Note

- 新任务默认允许公网、内网和同任务服务，默认阻断宿主及跨任务访问；只有可信宿主配置能授予例外，授权及诱饵设置在任务创建时冻结。
- 沙箱内安装、可写配置修改及向允许目标发送数据按既有权限执行，运行风险和审计缺口只作收尾提醒，候选代码仍按冻结的交付检查独立审核。
- 额外目录默认提供副本，显式直接只读/可写授权可生效；直接可写会立即影响宿主，报告明确说明这一影响不经过交付审核，清理不删除授权源目录。
- 诱饵默认不投放；开启后无冲突投放、只对验证兼容的工具/流量解密，其他通信预先免解密，匹配原值及约定常见编码且仅持久化最小证据，不能把未命中当安全或命中当恶意。
- 必须执行的隔离不能落实时不启动或停止任务并报告真实结果，内容审计故障则降级不解密并说明缺口；任务辅助资源与证据纳入现有监控、清理和保留机制。

## 目标与非目标

目标：使上述规则在任务真实入口、Docker 执行、MCP 结果和实际宿主最终输出中一致可观察，并更新 devdocs。

非目标：通用 DLP、全协议解密、任意数据流追踪、自动判断所有恶意行为、动态扩权、直接写入自动回滚、替换 Agent、宿主全局代理或网站系统。没有投放时不假装诱饵检测有效。没有实际证据时不宣称已确认外传。

## Public Interface / Behavior

### 配置及冻结

- 保留现有项目配置、模型档案、CLI/MCP 主流程。旧 network.hostAddresses 仍表示额外禁止的宿主地址，不改成放行项。
- 新宿主授权配置放在状态目录的专用 permissions 目录，以已注册 projectId 选择；项目配置只能引用资源需求，不携带可直接生效的宿主授权。具体字段由独立严格 Schema 定义，缺失表示没有额外授权，格式错误明确失败。
- 网络授权支持明确目标和端口，也支持用户显式选择的网段/广泛范围；文件资源使用命名条目，记录源目录、容器目标、copy/direct 模式及 read-only/read-write 权限。正常项目工作区保持副本模式。
- 新任务保存独立、版本化的生效策略快照和摘要，后续代码审查绑定的配置摘要必须包含生效授权及诱饵设置，避免只绑定项目配置而漏掉授权。
- 当前任务及恢复任务使用冻结快照。旧任务没有新快照时按原边界继续，不从最新宿主配置隐式扩权；输出 legacy 标记。遇无法保持原边界的恢复必须明确失败。
- 诱饵开关及通信审计支持清单属于任务冻结策略；默认关闭。项目不得通过声明敏感源路径、目标挂载或新代理自行获得宿主权限。

### 文件资源

- 授权资源有独立容器目标路径，不覆盖 /workspace、系统伪文件系统或任务控制面。目标重叠、路径歧义、不可实现的只读权限明确报错，不能静默扩大授权。
- 副本复用现有稳定读取、链接与归档校验；不为外部链接自动附带未授权资源。直接资源使用 Docker 的明确 bind 参数，不开放用户任意容器选项。
- 直接可写只表示允许，不声称一定发生修改；报告列出实际生效范围，并说明该范围可能已被直接修改、尚无完整变更清单。受控项目应用状态与直接共享影响分别表达。
- 最终检查容器使用同一冻结资源授权；副本和额外共享文件不自动进入项目交付清单，未经单独规则不自动写回额外副本。
- 清理删除任务副本与运行时资源，不递归删除用户授权源目录。目录中现有子挂载、链接和特殊端点若无法满足声明的边界，启动失败，不能假报隔离成立。

### 网络与代理

- 新任务允许任务外部内网；宿主接口、公网映射地址及其他任务网络属于默认拒绝集合，显式授权例外按冻结范围放行。同任务继续互通。
- 其他任务随后创建、停止及恢复不应使现存任务获得未授权跨任务访问。开发、检查、服务及审计代理都受相同边界约束；覆盖不了的拓扑必须明确拒绝或作为未验范围保留，不假报完成。
- IPv6 原本关闭；本次不以允许内网为由开放未验证的 IPv6 路径。已有宿主公网别名登记机制保留，不声称任意复杂 NAT 可自动识别。
- 代理 CA 私钥保留在可信任务辅助环境，只向开发端提供必要的信任证书。代理不发布宿主公网端口，不允许其他任务使用，不保存完整 flow。
- 解密接入以已验证调用组合为单位：版本、客户端库、信任库和调用配置。首批覆盖 curl/wget 与明确的 Python 客户端组合；改变 CA 参数、独立信任库、未知客户端/配置预先走免解密路径。
- 不通过全局代理变量感染未知子进程，不全局替换开发环境的系统工具。具体受控入口可采用独立适配器或显式客户端配置，必须满足上述可观察行为；无法可靠分类则保守免解密。
- 不自动重放任意业务请求，不用首次失败后重试冒充首次无感。免解密通道仍校验真实目标证书。代理故障时撤销内容接入或不启动内容接入，记录缺口；原有强制网络边界仍保留。

### 诱饵与证据

- 每任务生成随机、无有效服务权限的假凭据，不创建真实 AWS/OpenRouter 资源，不使用真实密钥作为诱饵。
- 优先独立文件或非默认 profile。不修改项目文件，不注入常见凭据环境变量，不覆盖/合并已有配置；已使用或可能改变凭据选择的目标跳过，记录投放/跳过状态。
- 任务私有清单保存匹配所需值；用户报告仅显示编号。清单、代理私钥和证据分别管理，清理运行资源时删除不再需要的私钥/原值，不把它们复制进持久化报告。
- 首版明确支持原文、URL percent 编码、标准 Base64、URL-safe Base64（约定有/无 padding）的一层表示；不承诺任意嵌套、拆分、加密或自定义变换。压缩内容仅在已验证、受容量限制的解码路径观察，超限/未知形式记覆盖不足。
- 扫描可见出站 HTTP 请求的目标、头字段值和正文；最小事件只含时间、目标主机/端口、诱饵编号、匹配形式、位置类别。位置不包含原始头字段值、完整 URL/query 或正文片段。
- 在写盘前筛选；日志、异常堆栈、代理默认输出及测试证据也不得泄露真实请求内容。匹配缓冲和资源需有界，超限不吞为无命中。
- 命中证明到达观察点，不证明远端收到，不自动定性恶意；AWS 的派生签名未出现诱饵原值也可能不命中，必须在范围说明中列出。

## Behavior Contract

- System under test：任务权限、隔离执行、可选诱饵通信观察及宿主最终报告。
- Trigger/input：注册项目创建任务、冻结配置、安装/文件/网络操作、开发结束、监督发现故障及收尾。
- Collaborators：用户控制的宿主配置、Docker、开发 Agent、mitmproxy 候选组件、系统证书/客户端库、既有采集与交付器。
- Observable result：Contract Note 五条，以及 tasks.md 的 B01–B22。
- Failure visibility：结果、结构化证据和最终用户报告给出拒绝原因、真实停止结果、实际授权、内容免解密/未知状态及已知缺口；不伪造回执。
- Forbidden shortcuts：全网解密承诺；项目自授权；直接共享后仍泛称宿主未改；审计故障取消强制隔离；无命中等于安全；未验证工具默认强制代理；仅夹具通过就声称真实入口已验。

## Testing Decisions

- 测试只通过以下公开行为边界：严格配置解析及冻结策略读取；网络规则规划输入/输出；授权资源准备结果；诱饵投放清单/文件；匹配输入/最小事件；真实 CLI/MCP、Docker、客户端及用户最终输出。
- 内部私有方法、特定函数调用顺序和自实现算法不得作为预期值来源。优先真实临时目录与现有 Docker 测试模式。
- 组件按验收点 red → 最小 green → 必要整理；每切片记录 red 和 green。只文档切片豁免 red，仍检查链接和实际状态。
- 先运行当前可用基线，再做定向测试；全套按 AGENTS 运行 lint/check/test 和 build。真实网络、证书、挂载及模型行为在 e2e.md，不用假对象替代。
- 参考：tests/unit/monitoring.test.ts、tests/unit/mcp.test.ts、tests/integration/runtime.test.ts、tests/integration/services.test.ts、tests/e2e/host-reporting.test.ts。

## Gate Decisions

- 环境：approved，D19 host-managed。只使用当前项目、临时测试项目及带任务标签的 Docker 资源；不初始化 Git，不 commit/push。
- 本地测试和构建：用户完整流程已授权，agent 执行。创建与清理专用临时容器/网络/测试监听端点，不触碰真实业务数据。
- 代理依赖：在确认本包后允许新增任务级成熟代理组件并固定版本，不能全局安装 CA 或代理，不更新无关依赖。
- 真实宿主模型：沿用已明确授权的 Codex DeepSeek 接口，仅发送合成最小项目和假凭据；不上传当前项目、真实用户配置或通信正文。授权范围没有变化，不重复请求密钥。
- 网站/生产：不适用；项目是 CLI/MCP，不重启真实业务服务。
- 提交要求：技能默认提交步骤由用户 D19 和 AGENTS 明确豁免；审查以当前树基线清单/摘要和改动记录取代 Git diff。不是偷偷初始化 Git。
