- 分类：权限边界；本次对齐已确认，尚未实施。
- 决定：网络例外限定目标及端口；文件例外限定明确路径及只读或可写权限。

- 不变量：一次授权不自动扩展到相邻路径、其他目标或端口；开发 Agent 不得自行扩大。
- 来源处置：细化 D2。网络身份解析、协议及文件提供方式留待明确，不把授权粒度等同于宿主直接挂载。

- 所需证据：允许准确资源；拒绝范围外访问；文件只读权限不允许写入。
- 未决：授权来源及冻结时机，策略无法落实时的处理；后续再讨论沙箱内部安装与敏感资源。

## D6：沙箱内安装和配置修改按现有权限允许，事后审查

- 分类：稳定行为契约；本次需求已确认，尚未实施新增策略。
- 决定：沙箱内安装软件、修改系统配置及用户配置，默认按现有操作系统权限允许执行，不因位于项目外或属于配置文件而额外阻断；保留事后审查与提醒。
- 权限边界：不因此授予 root、提权能力或宿主资源访问权。无权限的系统配置写入仍失败。
- 示例：安装工具修改沙箱内可写的 .bashrc 可以成功，宿主结合安装命令和任务目的审查；不能仅因配置被修改就认定恶意。
- 来源处置：继承 devdocs/decisions.md D6、D9、D10 的内部行为审计与提醒职责，明确正常安装场景；宿主及跨任务边界不变。
- 不得采用的捷径：把所有配置写入标为恶意；把允许安装解释为默认提权；把成功打开文件解释为已确认内容修改。
- 所需证据：正常安装可写配置不被额外拒绝；无权限写入明确失败；收尾展示已捕获证据、上下文和覆盖缺口，不声称完整采集。
- 未决：发送数据的默认处置及事后风险判断；用户显式资源例外的生效方式；隔离不可执行时的行为。
- 文档状态：added-new；issue-local / pending issue package。

## D7：允许目标的数据发送默认执行，事后判断风险

- 分类：架构与风险取舍；本次需求已确认，尚未实施新增策略。
- 决定：向网络策略允许的目标发送数据默认允许，不新增依据数据内容或模型推测进行实时外传阻断。宿主基于可得证据事后审查并报告风险。
- 示例：依赖下载、模型请求正常执行；有读取私钥并上传的证据时，收尾突出提醒。用户接受提醒时发送可能已经发生。
- 边界：继承 D5 的宿主及跨任务默认隔离；允许数据发送不授予额外文件读取权限，也不绕过已有资源限制。
- 风险判断：网络请求本身不能证明恶意；应结合数据来源、目的、任务关系与用户授权。不能证明读取与发送关联时，应明确不确定，不能声称已确认外传。
- 来源处置：继承旧 D4 对获准项目数据公网发送的取舍，结合 D5 扩展到允许的网络目标；与 D6 的事后审查保持一致。
- 不得采用的捷径：把所有联网判为恶意；因允许联网而省略已发现风险；声称已具备完整运行时数据流追踪；将 HTTPS 请求存在当作内容外传证据。
- 所需证据：正常依赖及模型请求不被额外拦截；明确的敏感读取与上传代码证据得到突出提醒；仅有并存读取和请求时报告关联不确定；覆盖缺口明确展示。
- 未决：事后发现运行风险与交付代码审查的关系；权限例外的生效方式；隔离无法落实时的行为。
- 文档状态：added-new；issue-local / pending issue package。

## D8：运行风险与代码交付分别处理

- 分类：稳定交付契约；需求已确认。
- 决定：运行期可疑行为只作事后审查与突出提醒，不独立暂停交付。最终候选仍按冻结的代码审核和检查策略决定能否应用。
- 示例：安装过程存在可疑上传，但最终候选正常且交付检查通过时照常应用并提醒；最终候选自身包含窃取私钥逻辑时，由代码审核拒绝。
- 来源处置：继承旧 D7、D10、D20 的提醒规则，明确与 D7 数据发送处置的关系。
- 所需证据：相同正常候选在存在运行风险时仍可按策略交付且报告风险；候选自身恶意时审核拒绝。
- 新讨论项：用户提出在常见配置位置放置假 AWS/OpenRouter 密钥，检查出站通信是否含诱饵；范围、通信观察方式及漏报语义未确认，尚未实施。
- 文档状态：added-new；issue-local / pending issue package。

## D9：诱饵密钥通信审计采用兼容优先

- 分类：架构与兼容性取舍；需求已确认，尚未实施。
- 决定：采用每任务无效诱饵密钥与支持的 HTTP/HTTPS 流量匹配；兼容的请求经审计代理观察，不兼容或不可观察的通信继续允许，并明确报告覆盖缺口。
- 边界：不因此开放 D5 默认禁止的宿主或跨任务目标；不关闭上游 TLS 证书验证来换取兼容；不覆盖真实开发凭据。
- 证据语义：命中表示在观察位置发现诱饵，不自动证明远端已收到或行为恶意；结合目的、请求位置和任务上下文事后判断，延续 D8。未命中不代表无外传。
- 来源处置：扩展 D7、D8；不采用无法检查即拒绝通信的方案。
- 待确认：诱饵放置位置与默认启用范围、匹配变换范围及证据保留；代理兼容性与绕过观察的准确机制待验证，不能仅靠设置代理变量声称覆盖全部请求。
- 所需证据：正常兼容请求可执行且命中可查；不兼容请求不因审计新增阻断；失败或绕过留下缺口；诱饵命中和恶意结论分开；未命中不输出安全保证。
- 文档状态：added-new；issue-local / pending issue package。

## D10：诱饵默认关闭，启用后兼容优先

- 分类：产品默认值与凭据隔离契约；需求已确认，尚未实施。
- 决定：诱饵投放默认关闭，默认不创建诱饵文件、配置项或环境变量。用户显式开启后，采用兼容优先方式。
- 启用规则：优先使用非默认配置档案或独立诱饵文件；不修改项目文件，不向常用凭据环境变量注入假值，不覆盖或合并既有用户配置；可能干扰正常凭据选择的位置跳过。
- 示例：AWS 诱饵可使用非默认 profile，但仍需核对是否与任务配置及实际使用冲突；默认凭据位置不因当前为空就自动占用。
- 取舍：接受诱饵更难被发现、覆盖范围较小，不以模拟真实凭据为由破坏正常开发。
- 可见性：记录实际投放清单及因冲突跳过的项目，报告使用诱饵编号，不把未投放或未命中描述为无外传。
- 来源处置：细化 D9 的默认启用范围与放置策略，D9 的通信兼容优先及 D8 的事后提醒继续有效。
- 所需证据：默认不投放；显式开启后仅创建无冲突的允许项；已有项目配置、环境变量与实际开发凭据保持不变；冲突跳过有记录。
- 未决：用户显式例外及诱饵开关的配置生效时机；无法落实隔离边界时的处置；匹配范围与通信证据保留。
- 文档状态：added-new；issue-local / pending issue package。

## D11：任务创建时冻结权限例外与诱饵开关

- 分类：稳定配置与生命周期契约；需求已确认，尚未实施新增配置。
- 决定：权限例外与诱饵开关的修改只对新任务生效；当前任务不动态追加、撤销权限或投放、移除诱饵。
- 示例：运行中开启诱饵，当前任务保持原配置，新建任务才按新配置投放；扩大网络例外同理。
- 不变量：同一任务的相关授权与诱饵策略绑定创建时的配置，恢复原任务不等同于新建任务，不借恢复偷偷更新策略。
- 来源处置：细化 D2、D4、D9、D10 的生效时机；继承现有任务配置冻结原则。
- 所需证据：配置文件修改不影响当前任务；新任务使用新配置；结果可查看本任务实际生效配置；恢复保持冻结配置。
- 取舍：需要新建任务才能变更相关配置，换取可追溯性和较简单的生命周期。
- 文档状态：added-new；issue-local / pending issue package。

## D12：必须隔离的边界失效时停止任务

- 分类：稳定失败处置契约；需求已确认。
- 决定：任务所需隔离规则无法建立，或运行中发现其失效时，不启动或停止任务，并报告原因；保留已有日志和现场，按保留策略处理。
- 示例：不能保证未授权宿主服务或其他任务的隔离时，不能仅告警并继续开发。
- 边界：通信内容审计不兼容或不可用按 D9 降级允许，不等于隔离边界失效；用户显式例外按冻结配置解释，不属于规则失效。
- 来源处置：继承旧 R10 失败关闭原则，结合 D5 新网络范围；不承诺未检测到的失效能被立即发现。
- 可见性：宿主结果和用户报告明确失败阶段、原因、停止结果及证据缺口；停止失败不得假报已停止。
- 所需证据：启动策略失败不派发开发；检测到运行边界失效后停止任务并留证；内容审计不可用不触发这一停止规则。
- 文档状态：added-new；issue-local / pending issue package。

### 六项行为说明

1. 系统对象：中转沙箱执行边界、通信审计、宿主收尾及用户报告。
2. 输入：任务创建时冻结的配置、开发操作、项目资源需求和宿主授权。

4. 可见结果：公网和内网默认可访问；宿主和跨任务资源默认隔离；沙箱内操作受现有权限约束，允许的安装、配置修改和发送行为事后审查。直接可写例外影响立即生效且单独说明。
5. 失败可见性：必须隔离的边界无法落实则不启动或停止并报告真实结果；通信内容审计不兼容则允许免解密通道，报告覆盖缺口，不关闭 TLS 校验。
6. 不得采用的捷径：把联网或配置变化直接当恶意；把审计缺失或诱饵未命中当安全；项目配置自行扩权；直接写入宿主后仍声称宿主未改；用代理环境变量宣称覆盖全部出站通信。

### 验收场景与所需证据

- 正常路径：内网依赖仓库可访问，沙箱内正常安装修改可写配置不被额外拒绝；候选合格后交付，报告说明可得审计结果。
- 失败路径：无授权宿主/跨任务访问被拒绝；检测到隔离不可落实时停止任务；停止失败必须报告，不能假报成功。

- 权限路径：仅项目内配置申请不生效；宿主授权后新任务生效；当前及恢复任务保持冻结配置。
- 诱饵关闭：默认不投放；启用后遇既有配置或凭据选择风险跳过，不覆盖真实凭据或项目文件。
- 诱饵命中：可观察请求的原值、约定 URL 编码和 Base64 形式匹配；只留最小元数据，不保留全文或片段；说明命中不等于远端收到或恶意。
