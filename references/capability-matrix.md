# 按需求比较候选能力

核查日期：2026-11-02。先根据运行条件选一条试配路线，再核对需求和默认配置。本文是基于官方资料与部分代码的**适配判断**，不是实测结果或最终选型。逐项证据和固定链接见[项目调研](projects.md)，需求编号见[需求](../devdocs/requirements.md)。

需求对齐后的网络基线见 [D4](../devdocs/decisions.md#d4允许任意公网阻止宿主机和内网访问)：默认允许任意公网及同任务内部服务互通，禁止宿主机、其他任务和外部内网（D13）。下文域名允许清单等属于候选能力及默认值比较，不代表必须限制为仅访问中转站或预设开发站点；实际适配按更新后的 I08 验收。

## 先选一条可验证的组合

| 路线 | 复用已有能力 | 仍需验证或配置 | 适用条件 |
| --- | --- | --- | --- |
| AIO Sandbox + 内置 Codex | 容器环境、MCP、异步终端、文件 API、模型配置 | 受限容器启动、出站策略、项目基线、取消清理和安全交付 | 先评估 Docker 开发环境；中转站支持所需协议 |
| OpenSandbox + 内层 Agent | Docker/Kubernetes、CLI/MCP、Codex 会话示例、egress/Vault | 固定镜像、平台策略、完整日志、文件交付；MCP 未覆盖的能力用现有 CLI/SDK 验证 | 希望先复用运行管理与策略组件 |
| abx + 本地 OpenSandbox + 内层 Agent | 以上底座，加现成 MCP 后台任务和 provider 接口 | 插件版本、工具与后端对应关系、任务取消和宿主复制路径 | 需要 abx 的任务接口；先比较它是否比直接调用 OpenSandbox 更合适 |
| OpenShell + 内层 Agent | CLI 委派、文件/网络/进程策略、凭据替换、文件同步 | 内核探测、Agent 镜像、专用中转站 profile、交付基线和返工 | 重视策略与凭据；后端及内核满足前提 |
| BoxLite + 内层 Agent | microVM、生命周期 API、文件复制、网络和凭据组件 | KVM、DNS 约束、宿主路径、任务接口；MCP 版本与策略暴露范围 | VPS 提供可用 KVM，愿意评估 microVM 路线 |
| Hullwork Sandbox + 内层 Agent | gVisor、会话 MCP、工作区检查点、对象与导出清单 | Kubernetes/CNI/存储、依赖镜像、域名出站策略和全量清理 | 已有或愿意维护 Kubernetes 环境 |
| 最小 Docker + 内层 Agent（对照） | 容器基础能力和现成 Agent CLI | 任务管理、策略、快照及交付需自行组合 | 用于估算实际适配成本；不计入 11 个仓库 |

建议第一阶段比较 AIO、OpenSandbox、OpenShell 与最小 Docker 对照；需要后台任务接口时测试 abx 的本地 provider，有 KVM 时再补 BoxLite。Hullwork 是否试配取决于 Kubernetes 条件。顺序来自部署与组件复用判断，不代表安全等级或已确认的优胜者。

Magpie 只在模型协议存在缺口时加入。PAL 只在委派逻辑确有价值且执行位置已受限时加入。Octo 是可选内层 Agent。Hullwork Site 属于后续网站发布参考。**这些组件不需要全部安装。**

## 对照保护要求 R03–R05、R10

这些能力只有在正确部署、限制宿主控制面并通过验证后，才能视为满足要求。工作目录、文件清单或凭据占位符都不能单独保证整个系统安全。

| 项目 | R03 完整执行边界 | R04 工作区边界 | R05 身份与配置 | R10 已找到的失败行为及范围 |
| --- | --- | --- | --- | --- |
| Magpie | 需外部运行时 | 不承担文件隔离 | 默认可发现账号/改 Agent 配置；用独立 HOME | 路由可故障转移；不代表隔离失败关闭 |
| abx | 取决于 provider 沙箱及 Agent 位置 | 上传/挂载范围和宿主入口需固定 | 按模板/环境提供最小凭据 | provider 不支持返回错误；完整启动链待试 |
| OpenSandbox | 容器/Pod；安全运行时按组合选择 | 独立沙箱及宿主路径允许清单 | Agent HOME 自建；可选 Vault | egress 安装失败关闭；整条任务链待试 |
| PAL | 默认 CLI 子进程不满足整进程隔离 | cwd 不限制文件访问 | 复制宿主环境；需外部清洗/隔离 | 主子进程超时退出不代表全部后代清理 |
| AIO Sandbox | 整个 Agent 放容器才覆盖 | 独立卷/复制由外层固定 | 专用 Codex 配置与容器 HOME | 配置语法校验会退出；容器启动失败待试 |
| BoxLite | 每 box 独立内核；宿主控制面另限 | 卷/复制接口仍由可信宿主管理 | 专用 HOME；可选 secrets 替换 | KVM/启动/代理故障和外层回退待试 |
| BoxLite MCP | 继承 BoxLite 边界 | 任意宿主路径入口待约束 | env/卷由调用者提供 | stop 可吞清理异常，不能只信成功文本 |
| Hullwork Sandbox | 参考方案 Kubernetes + gVisor | session 工作区；共享存储覆盖需注意 | 非 root、无 SA token；模型身份另配 | 策略依赖 CNI；启动/清理失败须实测 |
| Hullwork Site | 发布控制面，不承担本需求边界 | 构建上下文/制品范围 | 发布租户身份非内层开发身份 | 发布验证失败不等于开发隔离失败关闭 |

| OpenShell | 文件、进程、网络及凭据策略 | 按有效文件策略限制 | profile 占位凭据；需独立中转站身份 | 内核准入失败、策略校验等拒绝；宿主委派链仍需试 |

## 特别核对网络与凭据默认值

下表的证据均在[逐项目记录](projects.md)中。网络允许中转站意味着它能看到任务发送的内容；凭据替换不会阻止模型把已经获准读取的源码发往该中转站。

| 方案 | 易误判的默认行为 | 试配时必须核对 |
| --- | --- | --- |
| AIO Sandbox | 入站 JWT/TLS 与出站策略不同；示例放宽 seccomp | 使用收紧的容器配置；另设出站控制 |
| OpenSandbox | 默认 DNS 过滤不限制所有直连 IP；gVisor 与当前 egress 路径不兼容 | `dns+nft`、默认拒绝、平台拒绝底线、实际后端；Vault CA 与流式响应 |
| BoxLite | 网络默认开放；空清单放开；DNS 查询不受清单约束 | 宿主回环、DNS、既有连接；secrets 隐式放行的 HTTPS 目的地 |
| Hullwork Sandbox | 参考 NetworkPolicy 允许公共 HTTP/HTTPS 与 DNS | CNI 执行、实际私网/集群 CIDR；是否需额外域名策略 |
| OpenShell | 无端点规则时拒绝出站；L7 请求规则默认审计；附加 provider 会影响有效策略 | `--base`/`--full`、L7 `enforce`、专用 host/port/path/binary profile、精确内网授权 |
| Magpie / PAL / Octo | 配置发现、环境继承或独立上下文不能替代凭据隔离 | 专用 HOME/环境/配置；实际调用位置与上游，不复用宿主官方认证 |

## 新增 R11：行为审计与提醒

R11 的范围以 [D9](../devdocs/decisions.md#d9明确审计对象是隔离环境内部资源) 为准：记录内层程序对隔离环境自身用户配置、环境变量、密钥等敏感资源的可疑操作，收尾由外层审查并提醒。它不要求以虚拟机逃逸或宿主文件修改为审计场景。现有候选尚未按修正后的范围完成专项核查，不能将命令输出、网络日志或 Agent 自述直接认定为满足 R11，也不能因 HOME 独立就认为无需审计其中的可疑修改。D11 已明确采用重点资源审计，不要求全面记录内部文件操作，普通开发缓存不逐项报告；环境变量按实际可观察范围说明限制。具体入口覆盖和日志可信范围仍待明确，本表不新增任何候选“已满足”的结论。

## 目前仍需解决的共同缺口

1. **交付范围。** 默认复制整个项目，通过配置文件排除指定内容（D14）；先确定基线和排除项，再导入任务。工作区内也可能有不应交给中转站的秘密。
2. **宿主参数。** 固定 image、挂载、网络、端口、宿主导入导出目录和策略。内层任务不能用工具参数提升权限。
3. **可信结果。** 从受控执行器记录退出状态和日志，保留增删清单；Agent 可写日志不能独立证明测试成功。
4. **返工对应关系。** 记录任务 ID、基线、工作区、模型档案及会话 ID。保留文件不等于恢复模型会话。
5. **取消与删除。** 分别核对命令、后代进程、整个运行时、卷、检查点、对象、缓存和凭据；断开 MCP 不等于清理全部数据。
6. **安全应用。** 导出先落独立交付目录，处理链接、归档、二进制和原项目冲突，审核后再应用。

这些是待验收事项，不能据此断定必须自己开发。先用候选已有的 CLI、MCP、SDK、清单与策略完成[验证计划](../devdocs/validation.md)，再记录实际缺口。
