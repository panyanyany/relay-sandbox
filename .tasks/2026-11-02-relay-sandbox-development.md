# 中转沙箱开发任务

创建日期：2026-11-02。

当前状态：执行中，开发版核心闭环已落地；专项验收尚未全部完成。用户已于 2026-11-02 授权开始实施。

## 1. 目标与执行边界

实现中转沙箱：宿主 Agent 委派任务到 Docker 内开发 Agent，完成项目副本准备、开发、返工、可配置检查、合并应用、内部行为审计及收尾。宿主与开发 Agent 独立配置，默认均为 Codex，可选 Claude Code、OpenCode，允许混合组合。

先完成快速开发闭环，再补齐稳定化能力。中断恢复、租约监督和到期自动回收最后开发；首版仍必须有基本隔离、取消、超时、停止和手动清理。

本文供后续执行 AI 使用。创建本文不代表开始实现；收到明确执行指令后，按任务依赖顺序推进。技术栈沿用开发方案建议：TypeScript、Node.js 受支持 LTS、pnpm；首次执行 T01 时核对兼容版本并记录，不能把尚未核验的依赖写成已可用。

## 3. 编码及文件拆分规范

1. 必须有中文注释：函数职责、权限边界、关键步骤、状态变化和不直观的处理须用中文说明。解释原因和约束，不逐行翻译代码。
2. 避免向大文件继续堆代码。CLI、MCP 只做输入校验、调用与输出；业务逻辑进入对应模块。
3. 每个文件聚焦一种职责。自有源码及测试文件必须少于 500 行（最多 499 行，计入注释和空行）；300 行时检查拆分机会。接近上限时先拆职责，不删注释或压行规避。生成文件、锁文件及测试数据不计入源码阈值，但不能将手写业务伪装成生成代码。T01 将长度检查纳入 lint，审核时核对实际长度。
4. 禁止形成集中所有流程的 `manager.ts`、巨型 `utils.ts` 或单文件 Agent 分支。通用函数只有真实复用时再提取。
5. 各模块暴露少量明确接口，调用方向为入口→核心流程→适配器；配置类型与错误类型保持明确，禁止循环依赖。
6. 复用成熟库，不重写容器运行时、模型工具循环、路径匹配及三方合并算法。Docker 客户端不能接受任务传来的任意宿主参数。
7. 单元测试与集成测试按模块拆分。新增功能和修复补必要单元测试；隔离边界必须有真实 Docker 验证，不能只靠 mock。
8. 每个任务完成后运行相应检查；整体完成必须执行 `pnpm lint && pnpm check && pnpm test` 并修复。缺少环境时记录阻碍，不将未执行记为通过。
9. 不自动执行 git commit 或 git push。真实密钥、运行产物和本机路径不写入公开文档。
10. 整个任务完成后必须更新 `devdocs/` 作为功能文档，说明实际实现、使用方法、限制与已验证步骤；同时更新 README、AGENTS 文档索引和结构树。

11. 命名表达用途，三方输入采用 `baselineManifest`、`resultManifest`、`currentManifest`；不使用 B/T/H 等单字母业务名称。优先提前返回，建议嵌套不超过三层；复杂条件提取具名判断，保持控制流可读，不机械抽碎函数。
12. 错误处理执行[开发方案的错误处理规则](../devdocs/development-plan.md#错误处理与重试)：确定性错误立即抛出，仅明确临时故障有限重试；保留 cause 和堆栈，脱敏后在入口报告，清理异常不覆盖主错误。不增加 catch 后返回空值或自动放宽配置的兜底。
13. 依照[模块数据契约](../devdocs/development-plan.md#保持实现可维护)传递输入输出，按阶段需要实现，不预建泛型框架。源码依赖单向，合并、检查和应用之间由任务用例编排。

以下结构已按职责逐步创建。可按实现需要调整细分文件，调整后同步本文和 `devdocs/structure.md`。

relay-sandbox/

├── vitest.config.ts             # 测试分组与环境要求
├── src/
│   ├── cli/                     # 命令注册及展示，不放业务流程
│   ├── mcp/                     # stdio 工具、schema 与结果转换
│   ├── config/                  # YAML 读取、Zod 校验、生效配置
│   ├── projects/                # 项目标识与根目录注册
│   ├── tasks/                   # 分拆启动、查询、返工、取消、收尾
│   ├── workspace/               # 排除匹配、复制、基线、清单与差异
│   ├── docker/                  # 客户端、受控模板、执行与销毁
│   ├── agents/
│   │   ├── host/                # contract.ts 及各宿主接入适配
│   │   └── development/         # contract.ts 及各开发 Agent 启动/解析
│   ├── network/                 # 任务网络、策略安装和边界核验
│   ├── audit/                   # 采集接入、规则、覆盖、脱敏和报告
│   ├── delivery/                # 检查、结论绑定、合并、应用及备份
│   └── storage/                 # JSON 元数据、JSONL 事件、制品访问
├── images/                      # 固定开发镜像与受控测试服务模板

│   ├── unit/                    # 各模块逻辑与错误边界
│   ├── integration/             # 真实 Docker、网络和文件操作

首版采用单包模块化结构，不引入 Web 框架、微服务、通用运行时插件系统或数据库服务。CLI 与 MCP 共用核心接口。审计原生辅助程序确有必要时再增加独立目录，并记录权限及构建方法。

## 5. 自动记录进度的执行协议

后续 AI 必须直接更新本文，不仅在对话中报告：

1. 开始时读取总表，核对上次进度日志、真实代码及验证证据，选择依赖满足的首个任务。
2. 将任务状态改为 `进行中`，填写开始时间，在进度日志追加一条开始记录。
3. 按该任务的步骤实现，先运行与修改对应的最小有效检查，再运行所要求的完整检查。
4. 每完成一项任务，追加实际修改文件、验证命令与结果、遗留问题和下一步；填写对应审核栏。
5. 状态依次使用 `待执行 → 进行中 → 待审核 → 已完成`；遇到问题使用 `阻塞`，须记录原因和可以继续的独立任务。
6. 只有验收满足、证据存在且审核通过，才勾选已完成。自查时注明“执行 AI 自查”，不能伪造独立审核。
7. 阶段切换、失败、方向变化和中断前必须保存进度。再次接手从记录恢复，不重复安装、覆盖用户代码或跳过失败检查。
8. 运行日志和测试输出保存到被忽略的本机产物目录，在本文只写脱敏摘要和相对证据索引；外部环境不足标记 `未执行`，不得填写通过。

### T01：工程初始化与兼容性核验

- 文件：根目录工具配置、`src/cli/`、`tests/unit/`。
- 步骤：检查本机说明与现有文件；核对受支持 Node LTS；固定 TypeScript、Commander、MCP SDK、dockerode、Zod、YAML 解析及 Vitest 的兼容组合。创建单包工程及 lint/check/test/build 脚本，将自有源码和测试的少于 500 行检查纳入 lint，不一次创建空壳框架。
- 验收：最小 CLI 帮助可运行，类型与代码检查可执行；记录 Docker 客户端为社区库以及需要的 API 范围。当前无网站，不新增无需求的 Web 服务。

### T02：配置、双侧 Agent 契约与任务存储

- 文件：`config/`、`projects/`、`agents/host/contract.ts`、`agents/development/contract.ts`、`storage/`、`tasks/`。
- 步骤：实现项目标识、`hostAgent` 与 `developmentAgent` 独立配置，默认 codex；解析宿主私有模型档案引用。分开定义宿主接入与开发执行契约，禁止混合能力的大量可选字段。冻结有效配置摘要，建立 JSON 任务信息、JSONL 事件和产物目录。
- 验收：非法字段报错，秘密不进入日志；任务文本不能选择任意宿主挂载。不支持的 Agent 组合明确报错。首版不引入 SQLite 和自动恢复。

### T03：项目复制、排除与初始基线

- 文件：`workspace/`，对应独立复制、排除及清单测试文件。
- 步骤：完整复制项目，纳入未提交、未跟踪及 Git 忽略文件；只按显式配置排除。记录 baselineManifest 基线，处理复制竞态、模式、二进制、删除、符号链接及 Git 外部引用。
- 验收：F08、I09；不跟随链接读取宿主外部文件，不直接使用 worktree 的外部 `.git` 引用；不静默跳过大文件。内层无改动时差异为空，用户已有修改不算内层产出。

### T04：Docker 启停、基本隔离与资源限制

- 文件：`docker/`、`network/`、受控镜像及服务模板。
- 步骤：实现固定镜像、独立 HOME 和任务副本、环境允许清单、普通用户及受限权限。创建基本任务网络，限制宿主和外部内网访问；实现执行、查询、取消、超时、停止及手动删除。
- 验收：隔离或网络策略不可用即停止，不回退宿主。禁止 Docker socket、host 网络、任意宿主卷和特权参数。验证 CPU、内存、PID、输出限制；磁盘硬限额不支持时明确说明。核心 I01–I08、I10–I11 有真实证据，完整网络矩阵由 T09 补齐。

### T05：默认 Codex 开发适配与 CLI 闭环

- 文件：`agents/development/codex.ts`、拆分的 `tasks/` 用例及 `cli/` 命令。
- 步骤：核对内层 Agent 非交互参数及目标中转站协议；传入固定模型档案、解析输出和退出码。提供 start/status/logs/result/cancel/cleanup，支持有界日志游标。
- 验收：F01–F07；通过 CLI 在副本完成小任务并取得结果。Agent 工具及后代都在容器内，不批量继承宿主环境，不自动换中转站。尚未实现的审计能力显示缺口。

### T06：制品清单、差异与检查策略
