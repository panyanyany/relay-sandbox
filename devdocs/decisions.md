### D4：允许任意公网，阻止宿主机和内网访问

- 日期：2026-11-02。
- 状态：已确认，尚未实现或验证。
- 分类：网络访问边界及数据暴露取舍。
- 决定：内层开发环境默认可以访问任意公网，不要求逐站授权；禁止访问宿主机和内网。
- 取舍：便于安装依赖、查资料和访问开发资源；用户接受内层可能把获准读取的项目代码发送到其他公网地址。阻止代码向任意公网外传不作为本方案的保证。
- 适用边界：允许公网不授予额外文件、凭据或运行时管理权限。宿主机即使使用公网地址，也仍属于禁止访问对象。同一任务内部服务互通按 D13 放行。
- 依据与处置：继承其他项目、宿主配置和凭据的保护要求；将网络选择从候选建议明确为“任意公网可用、宿主及内网禁止”。不采用“中转站及开发站点逐项允许”作为默认需求。
- 受影响的操作：内层联网、依赖获取及网络边界验收；不改变 D3 的敏感文件排除要求。
- 不能采用的捷径：只阻止私网地址却放行宿主公网地址，或只设置代理环境变量便声称所有工具的网络入口都已受限。
- 所需证据：后续验证多个未预先登记的公网资源可访问；宿主和内网测试端点不可访问。按所选运行时覆盖直接 IP、域名解析、重定向及 IPv4/IPv6 等入口。
- 未决事项：实际网络策略和运行方式、同任务内部服务互通的实现；不在本轮配置或测试网络。
- 文档同步：已更新需求、架构草案和 I08 的验收描述。

- 日期：2026-11-02。
- 状态：目标已确认；审计对象按 D9 修正为虚拟机/隔离环境内部资源，尚未实现或验证。

- 未决事项：具体入口覆盖、正常行为规则；操作结果不明按 D20 处理；成功的可疑内部操作按 D10 处理。已受阻的操作按 D7 处理，记录缺失按 D8 处理。

### D8：审计记录缺失或采集失败时，明确提醒后仍可交付

- 日期：2026-11-02。
- 状态：已确认；审计范围按 D9 修正，尚未实现或验证。
- 分类：稳定审计故障与交付规则。
- 决定：本应采集的记录缺失或采集失败，但代码通过外层审核时，仍可交付；收尾须说明缺口及无法判断的范围。
- 用户可见结果：例如“修改已应用，但部分审计记录缺失，无法确认是否发生了对内层用户配置的可疑修改”，不能说“确认没有异常”。
- 适用边界：缺少记录不能证明敏感操作已受阻，也不能证明其已成功；有事件但结果不明时按 D20 提醒，不单独阻止交付。
- 取舍：行为审计作为辅助检查和提醒，不因采集故障单独阻塞审核合格的代码交付；用户接受可见性可能不足。
- 依据与处置：继承 D2、D6；不取消 R11 的采集要求，不改变宿主隔离要求。
- 不能采用的捷径：隐瞒缺失、捏造无异常结论、以故障可容忍为由省略采集，或把已有的敏感修改证据归为普通日志缺口。
- 所需证据：模拟采集不可用或记录不完整，验证合格代码仍可交付，收尾准确说明缺口和未知范围。
- 文档同步：已更新需求、架构草案和 A07。

- PAL 默认 CLI 权限、Magpie 的账号发现与配置切换、Octo 的终端沙箱范围都需额外约束。它们的委派或模型能力不能单独覆盖完整执行隔离。
- 保留工作区、恢复 Agent 会话、停止运行时和清空任务数据是不同操作。返工和清理需分别验收。

候选组合和条件见[需求对照表](../references/capability-matrix.md)。所有方案仍须通过原有验收，尚未决定增加自研封装。

## 核对选型结论

1. “没有确认开箱即用”不等于“没有现成工具”或“必须自己开发”。
2. “支持 MCP”需区分消费 MCP 服务和作为 MCP Server 被调用。
3. 子 Agent、独立上下文和切换模型不等于宿主文件隔离。
4. 只限制 shell 子进程，不代表主进程文件工具和外部 MCP 也受限。
5. 虚拟机内部隔离不会自动约束宿主侧 MCP 的挂载、复制和导出路径。
6. 官方外层模型不代表恶意补丁、工具结果和项目配置会自动变安全。
7. OpenShell 和 OpenSandbox 是不同项目；BoxLite 与 BoxLite MCP 是不同仓库。
8. 已讨论的相关候选和配套仓库为 11 个，清单应包含 NVIDIA OpenShell。

## D24：宿主定时汇总与分层清理（2026-11-02）

用户要求定时记录沙箱 CPU、内存等状态，用于崩溃回溯，并提供日志及相关资源清理。开发版由独立宿主进程采样，正常收尾删除运行资源并保留证据；到期回收通过独立监督器或 gc 执行。采样间隔、轮转容量和保留期均可配置。代码备份及任务元数据保留，避免自动删除恢复依据。实现、默认值及限制见[指标与清理](observability.md)。

## D25：行为策略基线与宿主授权（2026-11-02）

用户重新对齐并确认行为策略，取代 D4/D13 中禁止任务外部全部内网的旧表述。新任务默认允许外部网络和同任务服务，保护宿主及其他任务；明确宿主网络授权优先于默认拒绝。项目只申请资源名称，宿主独立配置授权，任务冻结后不可由模型扩权。无新快照的旧任务保持旧边界。

额外目录默认副本；显式直接只读/可写为例外。可写共享立即影响宿主，不受最终项目交付审核约束，必须独立提醒。正常内部安装和配置修改按现有操作系统权限允许。强制隔离失败停止；停止失败如实说明。运行期风险、未知和观察失败仅提醒，候选自身恶意由启用的代码审核拒绝。

诱饵默认关闭，独立无效假凭据、冲突跳过，不污染真实默认配置。显式受控工具入口仅覆盖实测组合；未知组合提前免解密，真实 TLS 继续校验，不自动重放。流量只保留最小匹配元数据，匹配不等于恶意/送达，零命中不保证安全。原值和常见编码支持边界见[行为策略](behavior-policy.md)。

完整已确认条款及架构影响见[行为策略需求包](../.rope/issues/behavior-policy/prd.md)和[决策台账](../.rope/issues/behavior-policy/grill-decisions.md)。组件与实际入口验收分开记录；以[实现验证记录](implementation-validation.md)为准。

## D26：项目访问方式可配置，默认隔离原项目（2026-11-02）

状态：需求已确认，2026-11-02 已实现于开发版；验证范围见[项目访问方式](project-access.md)。

主项目访问方式作为可配置选项。默认沿用独立副本，审核或配置的交付检查通过后应用；显式选择直接读写挂载时，沙箱可立即修改原项目，包括删除文件。直接模式的检查属于修改后的检查，不能描述为检查通过后才写入原项目。未显式启用时不得自动切换为直接挂载。其他宿主访问边界继续适用。

默认隔离只规定原项目与开发工作区分离，不限定独立工作区必须通过 Docker 归档传输；宿主独立副本加挂载可另行评估。现有额外目录授权不自动覆盖主项目。开发版通过宿主授权 `project.mode: isolated | direct` 配置，创建时冻结，默认不挂载原项目。直接模式与非空排除规则冲突时明确拒绝；事后检查前停止任务，独立候选容器不挂载原项目，最终仅核对内容并确认，不回写、不自动回滚。旧快照摘要保持兼容。详细操作与边界见[项目访问方式](project-access.md)。
