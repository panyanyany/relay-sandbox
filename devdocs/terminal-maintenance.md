# 终端会话故障与等待边界

重新接入普通请求失败后的会话时，继续使用原会话编号。后台 `status` 的 `lastTurnFailure` 保存最近一次请求错误，`backendFailure` 表示阻止接入的后端故障。兼容字段 `failure` 继续用于当前请求的失败观察。就绪检查只以 `backendFailure` 拒绝接入，并核对真实后台进程和原生会话身份。

在逐行终端等待审查时，可以按 Ctrl+C 退出。客户端取消信号关闭当前审查应答连接，后台已经接受的审查继续执行。后续可查询原会话。首次保存的开发请求仍完成一次派发，不因输出连接中断而丢弃。

公共 worker 客户端统一管理等待预算：普通查询为 5 秒，停止为 180 秒，审查不另设整个 RPC 的总超时。审查的冻结、检查命令和模型调用仍使用各阶段预算；连接错误立即传播。网页审查不叠加 650 秒进程超时。显式取消等待不会调用停止命令。

停止操作覆盖完整收尾过程。Docker 退出事件在停止期间等待操作结果：停止成功后视为预期退出，停止失败后仍检查并记录退出证据。不要在调用驱动停止前关闭 Docker 监测，否则失败后会丢失后续崩溃信息。

当前实现已删除没有产品调用方的启动能力发现辅助层、重复的结构化请求接口及直接 WebSocket 依赖。能力查询使用现有结构化驱动；MCP 所需的传递依赖保留。事件查询性能优化另行评估，本次未引入 Redis。

## 验证

回归入口：`session-worker-api`、`session-backend-lifecycle`、`session-recovery`、`session-worker`、`session-json-cli`、`terminal-command`、`session-runtime`、`session-review-command` 与 Webcoding 的 `relay-session-actions`。

这些测试使用合成驱动和连接，不代表真实模型端到端验收。统一终端候选版的原有发布门槛保持不变。

## 本轮处理范围

| 编码 | 处理 |
| --- | --- |
| TERM-REV-001 | 分开记录请求失败和后端故障，普通请求失败后允许重新接入 |
| TERM-REV-002 | 终端取消长审查等待，保留后台操作 |
| TERM-REV-003 | 完整停止成功后才关闭 Docker 监测，失败继续留证 |
| TERM-REV-004 | CLI 共用操作等待预算，网页审查复用阶段预算 |
| TERM-REV-005 | 网页故障提示改为开发 Agent 与后台诊断 |
| TERM-REV-006 | 删除无调用方的抽象和直接 WebSocket 依赖 |
| TERM-REV-007 | 暂缓事件查询性能优化，不引入 Redis |

全量测试中发现两处旧测试的时序依赖：Webcoding 停止测试改用 IPC 就绪回执；审计重复连接测试统一两次连接的受信脱敏配置，避免把异步文件校验完成顺序当成 API 保证。均未改变对应生产逻辑。
