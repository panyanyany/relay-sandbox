# 选择项目访问方式

状态：2026-11-05 新任务默认直接挂载原项目；可显式选择隔离副本。已有任务保持冻结模式。

## 配置并创建新任务

升级代码后先运行 `pnpm build`，已有 stdio MCP 会话须重启连接以加载新版本。此功能不要求修改开发镜像。

在宿主状态目录的 `permissions/<projectId>.yaml` 配置主项目模式。新任务没有此字段或没有授权文件时使用 `direct`。如需保留原先的隔离副本方式，配置：

```yaml
version: 1
project:
  mode: isolated
```

默认使用 `direct`；也可显式配置如下，再创建新任务。无需配置源路径，系统只挂载宿主登记的当前项目，容器路径固定为 `/workspace`。

```yaml
version: 1
project:
  mode: direct
```

不要在项目 `relay-sandbox.yaml` 中配置这个字段。该文件只能提供排除规则等项目选项，不能授予宿主写权限。模式创建时冻结；修改宿主文件不会改变已有任务，恢复和返工仍使用原挂载。旧冻结快照的摘要不因升级新增默认字段而变化。旧快照没有模式字段时仍按 `isolated` 解释，不自动改挂载。已有持久环境若与新任务模式不一致，会要求显式重置；系统不会自动删除环境。直接挂载仍保存审核快照，不代表取消全部复制。持久环境的直接模式复用创建时的任务基线，不额外复制隔离同步用的 `host-baseline`。

## 理解两种模式

| 行为 | `isolated`（显式选择） | `direct`（新任务默认） |
| --- | --- | --- |
| 开发工作区 | 复制到容器，与原项目分离 | 原项目读写绑定挂载到 `/workspace` |
| 新增、修改和删除 | 先影响副本 | 立即影响原项目 |
| 项目排除规则 | 按 `project.exclude` 过滤 | 不支持，非空时创建失败 |
| 检查与审核 | 应用前检查最终候选 | 修改后的事后检查 |
| `apply_task` | 核对候选后应用、记录备份 | 确认当前原项目仍匹配检查结果，不回写 |
| 拒绝或取消 | 未应用修改不进入原项目 | 不撤销已有写入，不自动回滚 |
| 正常清理 | 删除容器和任务副本 | 删除容器和任务副本，保留原项目 |

直接挂载采用 Docker 的[绑定挂载](https://docs.docker.com/engine/storage/bind-mounts/)，修改在运行期间就影响宿主。仍保存宿主基线、收集结果和候选快照供审核，避免重复向开发容器上传项目不等于取消全部复制。直接模式不会生成回写应用器的 `backup/applied.jsonl` 或自动回滚备份；收尾按现有保留规则清理快照。开始前应自行保存需要保留的版本。

## 处理排除规则和文件权限

绑定挂载整个项目不能按 glob 隐藏部分文件。如果项目存在 `project.exclude`，创建直接任务会明确失败，不会静默忽略排除规则。需要排除敏感文件时显式使用隔离模式。

开发进程仍以容器 UID/GID `1000:1000` 运行。宿主项目须允许该身份执行所需读写；系统不自动修改原项目所有者、权限或为开发 Agent 提权。Git 元数据也在直接挂载范围内，可被开发 Agent 修改。

原项目路径必须规范且无链接，并且不能与宿主状态目录或受保护系统目录重叠。子挂载、特殊文件和多硬链接文件明确拒绝。项目内普通符号链接保留，宿主快照不跟随读取；容器按自身命名空间解析目标，不因此获得外部宿主路径。外部 Git 管理引用仍受现有快照检查约束。

## 检查和返工

1. 开发完成后照常调用 `prepare_delivery`。直接模式会先停止本任务的开发、服务和观察环境，再核对原项目与收集结果一致。
2. 在独立候选副本上运行配置的检查。检查容器不挂载原项目，测试产生的文件不回写原项目。额外资源仍按其独立冻结授权提供。
3. 审查 `get_result`。直接模式的 `applicationPlan.kind` 为 `post_write_changes`，列出相对任务基线的变化；这不是等待回写的变更。
4. 满足配置的检查后调用 `apply_task`，确认原项目仍与审核候选一致。再次发生变化时拒绝确认，不覆盖宿主新内容。全部检查关闭时明确说明未执行检查。
5. 需要返工时调用开发入口。系统重启原开发容器，重新安装冻结网络与观察环境，继续使用原挂载；不能直接修改候选后要求回写原项目。
6. 完成或异常时清理并上报。检查被拒绝时，报告仍说明原项目可能已经改变。

恢复前校验目录设备号、inode 和 Docker 挂载信息。原路径被换成另一个目录时拒绝恢复。宿主并发修改仍无法被容器停止机制冻结；确认只能说明核对时内容匹配，不能承诺确认后的文件永远不变。

## 读取宿主报告

`get_result.policy.projectMode` 显示冻结模式。`report_task` 同时返回 `projectMode` 和 `deliveryKind`；直接模式的后者为 `post_write_check`。为兼容现有状态流转，完成确认后仍使用 `deliveryStatus: applied`，须结合 `deliveryKind` 理解为事后确认。

直接共享下不能可靠区分开发 Agent 与宿主并发写入，`originalProjectChangedByTask` 返回 `null`，而不是把审核拒绝解释为原项目未变。文字报告明确说明即时修改、事后检查和不自动回滚。额外目录的直接授权与主项目模式分开报告。

错误示范：在项目配置里允许自己直接写宿主；声明文件已被排除但实际挂载整个目录；审核拒绝后报告原项目未变；或把检查副本重新覆盖到原项目。

## 处理检查失败与大文件

直接模式在收集结果、准备检查及最终确认前停止任务资源，再遍历和核验项目。特殊文件、目录身份变化或挂载不一致会明确失败。准备检查失败后任务标为 `failed`，旧审核失效；不能把失败理解为原项目已回滚。停止失败会保留错误，不能声称所有进程已停止。

直接结果采集与隔离导出共用单文件 256 MiB 上限。超限文件明确报错，不静默忽略。宿主扫描和快照使用固定 64 KiB 缓冲区，读取期间增长和元数据变化也会失败。初始项目快照保留既有规则，不新增总容量限制。

恢复和返工共用启动流程。强制网络策略失败时停止任务资源；可选通信审计失败时保留原因并继续开发。降级记录无法写入任务状态时停止资源并抛错，避免丢失可观测性。
