## 划分执行职责

| 层次 | 职责 | 约束 |
| --- | --- | --- |
| 宿主 Agent | 与用户对话、拆任务、审核和收尾 | 默认 Codex，可选 Claude Code、OpenCode，使用可信接口；把内层返回内容视为不可信输入 |
| 委派控制层 | 准备工作区、启动运行时、管理任务、导出结果 | 掌握宿主机权限，必须限制路径、配置和运行参数 |
| 隔离运行环境 | 运行开发 Agent、调用中转站、修改授权文件 | 只接触本任务数据和凭据，不能控制宿主机运行时 |

宿主和开发 Agent 均独立可配置，默认 Codex，适配目标包括 Claude Code、OpenCode。中断恢复、租约和到期回收放到最后的稳定化阶段；首版保留正常返工、停止、超时及手动清理。

开发 Agent 可以替换。BoxLite 与 Octo 不需要绑定；Docker 本身也不是开发 Agent，容器内仍需能完成模型调用和工具循环的程序。

## 试配 Docker 路线

可以先用一个固定开发镜像和一个受限启动器试配。已有工具若能提供这些能力，就优先配置复用。

1. 在宿主机确认项目根和任务范围，记录基线版本以及已有未提交修改。
2. 从允许的文件生成独立项目副本，包含已有未提交修改和未跟踪源码，将初始内容记为任务基线。按配置文件排除指定内容，并避免复制指向宿主机的 Git worktree 元数据。
3. 为任务创建新的容器 HOME、配置和工作区，只注入指定中转站的专用凭据。
4. 在容器中启动开发 Agent。所有文件工具、shell、后台任务及 MCP 子服务都留在容器约束范围内。
5. 导出相对基线的修改、增删文件清单、日志与测试结果，交由宿主机审核。
6. 需要返工时保留受控会话；终结任务后停止后台进程，清理容器和任务临时存储。

不要把“独立 worktree”当作隔离机制：worktree 可能通过 `.git` 文件引用原仓库的管理目录。具体用快照、独立 clone 还是复制，需在实现前验证。

## 运行边界建议

| 方面 | 建议 |
| --- | --- |
| 挂载 | 新任务默认可写挂载已登记原项目；可选独立副本，其他宿主目录仍受限制 |
| HOME | 使用容器自己的 HOME，不挂载宿主机 HOME、全局 Agent 配置或认证缓存 |
| 凭据 | 使用明确的环境变量允许清单；不批量转发宿主环境，不把密钥烘焙进镜像 |
| Docker 管理 | 不暴露 `docker.sock` 或 Docker API，不允许内层更改宿主机挂载和权限 |
| 身份与权限 | 优先普通用户、削减 capabilities、限制提权，评估 Rootless Docker |
| 内核约束 | 保留适用的 seccomp 和宿主机安全策略；不直接照抄关闭隔离约束的示例 |
| 网络 | D25：新任务默认允许公网、外部内网与同任务服务，宿主及其他任务默认拒绝；宿主授权冻结为例外。旧任务无快照保留旧规则，见[行为策略](behavior-policy.md) |
| 资源 | 限制 CPU、内存、进程、运行时长和输出体积，明确磁盘限额的实现方式 |
| 清理 | 同一任务环境保留至收尾以支持返工；异常中断先停止任务进程，限期保留工作区与任务状态，期限可配置，到期清理；清理时处理任务卷、缓存、工作副本及含凭据的配置，先保存外层审计所需证据 |
| 审计 | 已确认检查内层自身用户配置和敏感信息操作，收尾提醒；不是检测虚拟机逃逸。采集、保护、覆盖与正常行为规则待明确 |

Docker 共享宿主机内核，存在运行时及内核漏洞的剩余风险；Rootless 可降低部分权限风险，不能代替路径和数据交付策略。参见 [Docker 安全文档](https://docs.docker.com/engine/security/)与 [Rootless 文档](https://docs.docker.com/engine/security/rootless/)。

“不使用 host 网络”也不等于不能访问宿主机或内网。出站限制需要独立设计，不能仅靠桥接网络这一配置宣称已经完成。

## 委派接口草案

优先检查候选是否已有合适的 MCP 或 CLI。[资料核查](../references/projects.md)显示 abx 已有后台任务 MCP，OpenSandbox 已有 CLI/MCP，AIO 已有异步终端，OpenShell 已有非交互 CLI。先按[需求对照表](../references/capability-matrix.md)试配，区分底层、桥接接口和完整流程。下面只是可能的接口，不是实现承诺：

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| `start_task` | 已授权项目标识、任务、已配置模型档案 | 任务 ID、启动状态 |
| `get_task` | 任务 ID | 状态、有限长度的日志、错误 |
| `get_result` | 任务 ID | 补丁、文件清单、测试记录、基线信息 |
| `cancel_task` | 任务 ID | 停止结果 |
| `cleanup_task` | 任务 ID | 清理结果与保留产物位置 |

模型可以选择允许的档案，不能通过输入参数任意指定宿主路径、导出目标、特权参数或未经允许的镜像。用户主动配置新档案与模型自行放宽策略应分开处理。

控制层拥有 Docker 或文件访问权限时，它本身就是信任边界。必须校验输入和导出路径，包括相对路径穿越、符号链接及归档条目。不要把通用“任意 docker run”接口当作受限委派接口。

## 导出并审核结果

建议交付包包含：任务 ID、基线标识、变更文件清单、补丁或文件差异、命令退出码、测试输出以及失败说明。内层声称“测试通过”与实际可检查的执行记录分开保存。

交付检查按 D17 配置：默认仅宿主机 AI 代码审查，用户可增加测试或关闭 AI 审查。已启用检查失败或无法运行时按 D19 先修复或重试，仍不通过则暂停交付并说明，不自动跳过检查。全部交付检查关闭时按 D18 直接应用并说明未执行检查，无法可靠解决的冲突仍须询问。代码审查启用时，建议覆盖代码、依赖、构建脚本、项目 Agent 配置、hooks、符号链接和新增文件。不要直接执行内层返回的 shell 指令、加载其配置，或自动运行项目生命周期脚本。必要的构建和复测先在隔离环境完成。

原项目后续修改与回传结果冲突时，按 D16 由宿主 Agent 尝试合并，保留双方修改意图；无法可靠解决则暂停应用并询问用户。最终合并结果适用当前交付检查配置。

独立工作区只防止开发期间直接改原项目。恶意内容若随审核通过的补丁进入项目，后续仍可能生效；交付边界必须独立验证。

日志、补丁、归档和测试输出均是不可信数据。收集结果不能额外授予内层宿主机工具权限，也不应原样回显凭据。

行为审计以 [D9](decisions.md#d9明确审计对象是隔离环境内部资源) 修正后的范围为准：检查内层程序对隔离环境自身用户配置和敏感信息的可疑操作。宿主文件保护与内部行为审计是两个验收范围；不能将内部配置修改成功等同于宿主隔离失效。

内层可修改的文本日志与控制层或运行边界生成的记录，须标明来源和可信范围。已按 D11 选择重点资源审计，不要求全面记录内部文件操作；普通开发缓存不逐项报告，环境变量按实际可观察范围说明限制。当前部分内核采集与可选诱饵通信观察各有覆盖边界，不能因命令输出或零命中认定满足全面审计。普通内部安装按现有权限允许，线索及缺口只用于收尾提醒。

[D7](decisions.md#d7被阻止的敏感资源操作只提醒不单独阻止交付) 与 [D8](decisions.md#d8审计记录缺失或采集失败时明确提醒后仍可交付) 保留：受阻的内部敏感操作或采集缺失只提醒，不单独阻止审核合格的修改应用。[D10](decisions.md#d10成功的可疑内部修改只提醒不单独阻止交付) 已确认成功的可疑内部修改也只提醒，不单独阻止审核合格的代码交付；D20 已确认操作结果不明也只提醒，报告必须明确未知结果。

## 尚未确定

新任务默认直接挂载原项目，可选完整开发副本；D25允许公网和外部内网，宿主与其他任务默认拒绝，可冻结授权例外；外层按配置检查后应用。首选路线为直接封装 Docker，CLI 与 stdio MCP 复用任务控制层；开发 Agent、具体网络及审计机制和补丁应用实现仍待验证。选择标准见[验证计划](validation.md)，决策状态见[决策记录](decisions.md)。

## 行为策略模块边界

- `permissions/` 校验宿主配置并冻结快照；项目 `resourceRequests` 只命名。项目配置与策略双摘要绑定审核。
- `network/` 分配专用任务地址池并规划规则，`docker/runtime.ts` 建立强制隔离后才返回可执行环境。保留任务池整体拒绝覆盖以后创建的任务；不依赖轮询补跨任务规则。
- `resources/` 校验路径和挂载边界，复制独立资源或生成明确的只读/可写挂载；恢复和候选检查复用任务副本。
- `tasks/environment*.ts` 组合可选诱饵、代理、公共客户端工具及最小状态。代理共享开发网络命名空间，因此出口仍受同一强制网络规则限制。
- `traffic/` 与固定 Python 脚本实现受控客户端、TLS 代理和最小匹配。开发端只有公共证书，私钥及原值匹配清单保留在宿主私密目录/辅助代理。
- `reporting/` 从宿主冻结事实及有界证据生成文字和结构化结果。直接可写影响与项目应用分别报告，观察缺口不改变代码审核结论。

停止、恢复、监督及到期回收由任务生命周期统一协调。强制隔离错误与可降级内容观察错误分开处理；不得把停止失败记录为已停止。源码每文件少于500行，入口、资源处理、观察和报告各有独立模块，避免继续扩大任务入口文件。
