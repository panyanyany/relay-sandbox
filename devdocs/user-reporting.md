# 完成异常上报

宿主 Agent 在审核和收尾后调用 `report_task`，把返回的 `reportId` 和 `userMessage` 原样作为最终用户回复。报告从宿主保存的事实生成，不接受模型自行填入交付状态。存在审计记录或覆盖缺口时，即使代码获准交付也会提醒。

## 执行顺序

1. 调用 `get_capabilities` 了解能力，再通过 `run_task` 派发已准备任务。
2. 使用 `get_task` 或 `wait_task` 查询进度。结果中的 `nextAction` 指示当前步骤。`checking` 且 `deliveryPrepared=false` 表示开发结果已收集，需要 `prepare_delivery`，无需继续等待开发。
3. 准备最终候选并完成检查后，读取候选、差异、`get_result.applicationPlan`、审计和监控信息，提交结构化审核。最终候选未准备时拒绝提交审核。
4. 按冻结策略决定是否应用。拒绝和待处理结论阻止已启用审核的交付；代码审核结论评价最终候选和应用计划，运行期敏感访问及覆盖缺口单独上报，不因此拒绝正确候选。
5. 任务结束时清理运行资源，再调用 `report_task`。需要用户解决冲突时可先上报待处理情况，按保留策略保留工作区，不应先销毁候选。
6. 向用户输出工具返回的报告标识与完整文字。CLI 可使用 `report <任务ID>` 生成同样的报告。

`get_result` 提供有界的聚合审计摘要；完整事件用 `get_audit` 分页读取。应用计划详情用 `get_delivery_plan` 分页读取，不能在候选项目中查找宿主元数据。

报告包含任务及摘要、审核结论、风险分类和证据、交付状态、本任务是否应用修改、审计状态及缺口、清理状态，以及指标记录索引。上报文字最多展示 20 项代码风险和 10 项敏感访问摘要，完整记录仍保存在结构化报告。缺失或部分应用时，原项目影响为未知，不会声称未改。

## 区分生成和输出

`report_task` 将报告保存为任务目录的 `user-report.json`，返回 `emissionStatus=prepared`。这个状态只证明报告已生成，不证明已经发给用户。报告绑定当前事实，后续返工、审核、应用或清理会使旧报告失效。

客户端接入方捕获实际最终回复后，可以调用 `recordUserEmission` 校验标识和完整文字，写入 `user-report-emission.json`，标为 `emitted`。MCP 不提供让模型自行声称“用户已收到”的回执工具。缺少报告、遗漏或改写正文、绑定旧报告时，校验失败。`emitted` 证明输出已发出，不代表用户已经阅读；没有接入该输出校验的客户端，不能仅凭报告文件声称已验证送达。

## 验证真实宿主会话

测试 `tests/e2e/host-reporting.test.ts` 使用真实 Codex 宿主和 DeepSeek 模型，经实际 stdio MCP 发现能力、派发开发、等待、读取候选、审核、清理和上报。开发侧实际 Codex 连接假中转站，容器仅接收假凭据。测试覆盖恶意代码被拒绝、正常代码通过但发生敏感诱饵读取，以及正常代码对照。测试接收实际最终消息事件，并与输出文件和宿主签发报告逐字比较。

准备镜像、构建 CLI，并安全注入 `RELAY_LIVE_KEY` 后显式执行：

```sh
RELAY_HOST_REPORT_TEST=1 RELAY_ATTACK_EVIDENCE_DIR=.local/evidence pnpm exec vitest run tests/e2e/host-reporting.test.ts
```

测试会产生真实 API 用量。输出目录保存结构化结论、实际工具调用轨迹和输出校验回执。默认单元测试跳过该组。

Codex 测试通过启动参数只信任本项目 MCP，并显式传入开发侧所需的假凭据环境变量名称，不修改用户现有配置。`host-config` 生成的 Codex 片段包含该服务的 `default_tools_approval_mode="approve"` 及档案对应的 `env_vars`，用于授权本服务工具和转发指定开发凭据；合入前需确认信任本地服务。该配置依据 [OpenAI 官方 MCP 配置说明](https://learn.chatgpt.com/docs/extend/mcp)。宿主 shell 在测试中禁用。

Claude Code 和 OpenCode 宿主可使用相同 MCP 协议，但其完整用户上报会话及输出回执尚未完成同等验证。任务事件订阅已支持，见[任务事件](task-events.md)；宿主自动唤醒仍未支持，客户端续接须独立验证。

## 阅读行为策略结果

`get_result.policy` 和结构化用户报告提供冻结策略、资源模式、直接可写宿主影响及最小流量证据。宿主权限路径只允许由用户在任务外配置，模型不能通过 MCP 扩权。

报告中的“未由本任务应用原项目修改”仅描述项目交付步骤。直接可写授权可能已经改变宿主源；报告必须同时说明。流量命中只是线索，不等于恶意、远端收到或完整泄漏结论。缺失、损坏、轮转和截断证据均说明覆盖缺口；零命中不等于安全。审计异常和正确代码可同时出现，应分别说明。

新增四场景的真实宿主验收记录在[行为策略验收](../.rope/issues/behavior-policy/e2e.md) E5。未完成的场景不能沿用早期三场景测试作为通过依据。

2026-11-02行为策略四场景已通过真实Codex/DeepSeek宿主输出验证，均保存emitted回执：命中但正常代码交付、恶意候选拒绝、直接可写即时影响提醒、观察缺失仍交付并提醒。该结论只覆盖合成项目和已记录配置，不替代其他宿主客户端验收。

## 回执版本与采样变化

报告快照与关键事实版本分别校验，普通采样时间变化不会拒绝已输出快照。关键风险变化仍使报告过期。细节和错误示范见[维护性修复](maintenance.md)。

## 追溯诱饵命中的调用

结构化命中附带可选调用关联，文字摘要展示环境、请求编号、调用编号、工具与容器内 PID，并注明客户端声明未经内核核验。旧事件显示未关联。字段、启用步骤和证据边界见[调用关联](traffic-correlation.md)。
