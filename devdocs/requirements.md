# 需求

状态：核心需求已于 2026-11-02 经用户确认，尚未实现或验证。确认范围见[需求对齐小结](decisions.md#本轮需求对齐小结用户已确认)。具体技术方案与实现细节留待后续设计；[验证计划](validation.md)仅记录验收标准，本轮不执行。

## 背景与问题

用户希望使用中转站的大模型进行开发，但担心中转站篡改模型输出或返回恶意工具调用，进而读取其他项目、窃取用户目录中的密钥，或写入长期生效的钩子和配置。

这里的“投毒”指对模型行为和返回内容的不信任，不限于训练数据投毒。外层使用官方接口，内层使用中转站，是用户期望的分工；外层仍需把内层输出视为待审查材料。

宿主 Agent 与 Docker 内开发 Agent 独立可配置，默认均为 Codex，可选 Claude Code、OpenCode 等；允许两侧选择不同工具。各适配能力须验证，不支持的组合明确报错。

## 用户明确的使用方式

1. 在宿主机进入自己的项目文件夹。
2. 像平常一样启动所选宿主 Agent，使用可信接口，正常对话；默认 Codex，也可选择 Claude Code、OpenCode。
3. 在对话中要求“在隔离环境里，使用某中转站的某模型完成指定开发任务”。
4. 系统准备隔离工作区，在其中运行开发 Agent 并配置指定接口。
5. 开发完成后，把修改和执行结果交给宿主 Agent。
6. 宿主机按配置执行交付检查，默认由 Codex 审查代码；通过后可直接应用修改并汇报结果，无需每次再次询问用户。需要返工时，将问题交回隔离环境处理。
7. 环境保留到整个任务收尾，再清理运行资源。宿主 Agent 检查内层行为审计记录；发现对隔离环境内部用户配置或敏感信息的可疑访问或修改尝试时，在收尾汇报中提醒用户。

用户不需要为了日常交互手动进入容器或虚拟机，也不希望更换宿主 Agent 的交互方式。

## 审核通过后应用修改

已确认：交付检查可配置。默认由宿主机 AI 审查代码，没有问题即可通过，不默认强制单元测试等额外检查。用户可以增加单元测试等检查，也可以关闭宿主机 AI 代码审查。外层按当前配置判断交付条件；内层完成说明不能替代已启用的检查。依据见 [D17](decisions.md#d17交付检查可配置默认仅宿主机-ai-代码审查)。

本文“审核通过”指满足当前配置的交付检查。关闭代码审查不取消行为审计、收尾提醒、隔离和冲突保护。全部交付检查关闭时直接应用修改并汇报，无需额外确认，明确注明“未执行交付检查”；无法可靠解决的冲突仍暂停并询问。依据见 [D18](decisions.md#d18全部交付检查关闭时直接应用并说明)。已启用的检查失败或无法运行时，先尝试修复或重试；仍不通过则暂停交付并说明原因，不自动忽略或关闭检查。返工和重试仍受取消、超时及资源限制约束。依据见 [D19](decisions.md#d19已启用检查失败时先修复或重试仍不通过则暂停交付)。

原项目在内层开发期间再次发生修改，导致回传冲突时，由宿主 Agent 尝试合并并保留双方修改意图；无法可靠解决时暂停应用并询问用户，不静默覆盖。最终拟应用的合并结果适用当前交付检查配置。依据见 [D16](decisions.md#d16宿主机-codex-尝试合并冲突无法可靠解决时询问)。

内部敏感操作已确认受阻，或审计缺失、采集失败时，不单独阻止审核合格的代码应用，但必须提醒。成功的可疑内部修改也不单独阻止交付，须明确提醒；操作结果不明也不单独阻止交付，须明确提醒未知结果。依据见 [D20](decisions.md#d20审计操作结果不明时提醒不单独阻止交付)。依据见 D2、D7、D8、D9、D10 的[决策记录](decisions.md)。实现与验证状态见[实现验证记录](implementation-validation.md)。

## 必须保护的内容

| 对象 | 要求 |
| --- | --- |
| 其他项目 | 内层 Agent 不得读取或修改本任务授权范围之外的项目 |
| 宿主机用户目录 | 不得借用宿主机 HOME 访问公共配置、凭据、历史和其他个人数据 |
| 密钥和会话 | 不向内层交付宿主机官方接口密钥、SSH 密钥、云凭据等无关凭据 |
| 宿主机持久配置 | 不得写入全局 Agent 配置、用户启动文件、全局 hooks、计划任务等 |
| 宿主机控制能力 | 不向内层暴露 Docker 管理接口、宿主机工具调用权限等越权入口 |
| 原项目 | 内层在独立开发副本中工作；修改按宿主侧配置的交付规则进入原项目 |

工作目录限制应覆盖文件读写工具、shell、搜索、后台进程和内层可用的 MCP 服务。只改变进程当前目录，不构成隔离。

项目内的 `.env`、证书、生产凭据或敏感数据通过排除配置控制是否交付；不承诺自动识别并排除。未配置排除的项目内容默认进入副本。

## 准备项目开发副本

已确认：默认向内层提供整个当前项目的独立副本，通过配置文件排除不想交付的文件或目录。内层可以查看副本中的其他源码和测试，不默认只提供与本次任务直接相关的文件。用户接受中转站能接触交付副本中较大范围的项目代码，以换取完整开发上下文。

副本不授予内层原项目的直接写权限，也不扩展到其他项目或宿主 HOME。副本包含已有未提交修改和未跟踪源码，按配置文件执行排除；初始内容属于任务基线，不得误算为内层新增产出。依据见 [D12](decisions.md#d12项目副本包含未提交修改和未跟踪源码)。未被配置排除的项目内容默认纳入，不自动沿用 Git 忽略规则，也不按文件类别或大小静默省略。复制不得跟随外部链接读取宿主未授权资源。配置文件名、格式、匹配规则和 Git 元数据的安全处理待设计。依据见 [D14](decisions.md#d14默认复制整个项目通过配置文件排除内容)。具体生成副本的方法尚未选择。决定依据见 [D3](decisions.md#d3默认交付完整开发副本按规则排除敏感文件和无关产物)。

## 允许外部网络，保护宿主和其他任务

2026-11-02 行为策略对齐取代早期的“默认禁止全部内网”：新任务默认允许公网、任务外部内网及同任务服务。默认拒绝宿主接口、登记的宿主公网映射和其他任务。用户接受获准读取的项目内容可能被发送到允许目标；网络通信本身不等于恶意。本项目不提供通用防泄漏保证。

只有宿主 `permissions/<projectId>.yaml` 能授予例外。项目配置仅申请资源名称，MCP 不接受临时扩权参数。创建时冻结授权和诱饵设置并纳入审核摘要；运行及恢复沿用原快照。旧任务没有快照时保持旧边界，不自动获得新权限。

额外目录默认使用独立副本，也可明确选择直接只读或可写。直接可写会即时影响宿主源目录，不等待交付审核。宿主报告必须独立说明这种可能影响；清理不得删除授权源。

普通安装命令可按容器用户现有权限修改内部系统或用户配置，不自动提权。强制隔离建立失败不派发开发；检测到隔离失效需要停止，停止失败须明确报告。内容观察失败只留下覆盖缺口，不能因此放宽隔离或单独阻止正确代码交付。


## 保留任务环境并在收尾时审计

开发顺序已调整：先实现正常任务、返工、取消、超时及手动清理，中断恢复、租约与到期自动回收放到最后的稳定化阶段。以下生命周期要求保留为完整目标，不作为快速开发首版全部完成的声明。

已确认：同一任务的环境保留到整个任务收尾，审核需要返工时沿用原工作区和开发环境，收尾后清理。保留环境不取消超时、取消和资源限制要求。异常中断后停止任务进程，暂时保留工作区和任务状态，供后续继续同一任务；保留期限可配置，到期清理。恢复不承诺保留进程内存或原执行位置，具体机制及期限默认值待设计。依据见 [D15](decisions.md#d15异常中断后停止进程限期保留任务现场)。决定依据见 [D5](decisions.md#d5任务环境保留到整个任务收尾)。

内层的一些行为须留下审计记录。审计对象是**虚拟机/隔离环境内部**的用户配置和敏感信息，例如内层自己的用户启动文件、Agent 配置、环境变量和密钥。宿主 Agent 在收尾时检查可疑访问或修改尝试，重点关注与任务无关的配置修改，并提醒用户。该要求不以检测虚拟机逃逸或宿主文件修改为目标，宿主保护仍由隔离边界承担。范围以 [D9](decisions.md#d9明确审计对象是隔离环境内部资源) 为准。

已确认采用重点资源审计：覆盖内层用户启动配置、Agent 配置、凭据文件等敏感目标的访问和修改尝试，不要求全面记录所有内部文件操作；普通开发缓存不逐项报告。环境变量相关操作按实际可观察范围说明限制，不承诺记录每次进程内部读取。依据见 [D11](decisions.md#d11采用重点资源审计)。

内部敏感操作无论被阻止、失败还是成功，都属于需要检查的对象。不能因为目标在内层 HOME 中就一概忽略，也不能把正常开发所需的每次读取都判为异常。正常操作规则仍待定义；内部修改成功不直接表示发生宿主越界。

已确认：可疑敏感操作明确被阻止，且代码通过外层审核时，照常应用，并在收尾说明操作目标、动作和受阻结果，无需另行确认。决定依据见 [D7](decisions.md#d7被阻止的敏感资源操作只提醒不单独阻止交付)。

审计记录缺失或采集失败时，审核合格的修改也可交付，但须说明缺口和无法判断的范围，不能将“未能审计”说成“没有异常”。这不取消采集要求，也不放宽宿主隔离要求。决定依据见 [D8](decisions.md#d8审计记录缺失或采集失败时明确提醒后仍可交付)。

已确认：可疑内部配置修改即使成功，项目代码通过外层审核后仍照常应用，收尾明确提醒目标、动作和成功结果，无需增加用户确认。依据见 [D10](decisions.md#d10成功的可疑内部修改只提醒不单独阻止交付)。

环境清理前保存外层所需的审计证据，不只依赖内层自行总结，记录和提醒均不泄露秘密值。具体资源清单与入口覆盖、正常行为规则、采集与保护方式、保留期限仍待设计和验证。决定依据见 [D6](decisions.md#d6保留行为审计记录收尾审查并提醒用户)。

| 编号 | 能力 | 期望结果 |

| R01 | 宿主机委派 | 从现有对话发起任务，无需用户手动进入隔离环境 |
| R02 | 指定模型配置 | 选择配置好的中转站与模型，兼容性需逐项验证 |
| R03 | 完整执行隔离 | 开发 Agent 及其所有执行入口都在约束范围内 |
| R04 | 独立工作区 | 默认复制整个项目，通过配置文件指定排除项，限制对其他目录的访问 |
| R05 | 独立身份与配置 | 内层有自己的 HOME、配置和最小凭据集合 |
| R06 | 任务执行 | 能修改文件、安装必要依赖、构建和运行测试 |
| R07 | 任务管理 | 查询进度、取回结果、取消任务；同一环境保留至任务收尾以支持返工，之后清理运行资源 |
| R08 | 可审查交付 | 返回修改差异、增删文件、执行记录和测试结果 |
| R09 | 审核与返工 | 宿主侧交付检查可配置；默认 AI 代码审查，可增加测试或关闭 AI 审查，并支持返工 |
| R10 | 失败关闭 | 隔离启动失败时停止任务，不自动改在宿主机执行 |
| R11 | 内部行为审计与提醒 | 记录内层程序对隔离环境内部用户配置、环境变量、密钥等敏感资源的可疑操作；外层收尾审查并提醒，已接入部分内核采集，覆盖限制见实现验证记录 |

| R12 | 定时回溯与资源清理 | 定期保存 CPU、内存等运行摘要；沙箱崩溃后仍能读取宿主日志；配置日志轮转、保留及任务资源清理 |

MCP 是优先讨论的接口形式，不是唯一可接受形式。现成 CLI 配合调用说明或少量脚本，若能满足同样流程，也可接受。

## 范围与取舍

- 当前主要是个人 VPS、单用户、多项目的场景，不以多租户平台为前提。
- 已有 Docker CLI/MCP 开发版；当前实测范围见[实现验证记录](implementation-validation.md)。
- 优先验证已有项目；“没有验证过完整方案”不能写成“没有现成项目”。
- 开发版采用 Docker；Agent 和模型档案分别配置，完整专项验收仍需推进。
- 不要求专门开发新的 Agent、模型网关、沙箱内核或网站部署系统。
- 运行隔离不等于产出代码可信；默认启用宿主机 AI 代码审查，用户可配置关闭；审查不能被描述为绝对安全保证。

## 可选诱饵与通信观察

诱饵默认关闭。开启后，只在独立非默认凭据文件投放明显无效的 AWS/OpenRouter 假值，不注入常用凭据环境变量，不覆盖或合并已有配置，冲突跳过并留记录。同任务恢复沿用原值，代理证书和运行目录重新建立。

仅已验证的工具、版本、库、信任配置和显式调用组合解密。未知组合在首个业务请求前免解密；保持正常 TLS 验证，不在请求开始后自动重放。当前组合及调用方式见[行为策略](behavior-policy.md)。内容过大、未知编码、代理退出等均须说明覆盖不足。

只记录时间、目标主机/端口、诱饵编号、编码和出现位置，不保存请求全文、片段或诱饵原值。匹配支持原值、percent、标准及URL-safe Base64；签名派生值和任意变换不保证匹配。命中不等于恶意或目标已收到，未命中不等于安全。运行期线索用于提醒，候选代码自身恶意仍由启用的交付审核拒绝。
