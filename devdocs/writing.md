# 文档写作规范

编写文档时，先确定读者要完成的任务，再选择保存位置。本文按 GOV.UK 内容设计指南的任务导向和 ASD-STE100 的清晰表达原则，约定本项目的中文写法。

## 选择保存位置

| 内容 | 位置 |
| --- | --- |
| 适用于不同环境的项目需求、开发与运维说明 | `devdocs/` |
| 可公开的外部资料链接、摘要与调研记录 | `references/` |
| 本机专用或私有的项目说明 | `.local/devdocs/` |
| 私有外部参考资料 | `.local/references/` |

README 用于说明项目目标、当前状态和文档入口。AGENTS.md 用于保存协作规则和文档索引。

公开文档使用相对路径或明确的占位符。本机绝对路径、服务标识及私有配置放入 `.local/`；真实密钥不写入文档。`.local/` 已在 `.gitignore` 中排除。

## 先写读者要做的事

- 标题说明任务或内容，如“导出并审核结果”“验证访问边界”。
- 开头给出操作、适用范围和状态，再补背景与原理。
- 有顺序的操作使用编号列表。每一步写清动作、对象和预期结果。
- 命令前说明前提和执行位置，命令后说明如何确认成功。
- 参数、候选方案和验收条件使用表格，便于比较。

## 使用短句和一致术语

- 使用简体中文、主动语态和明确的动作词。
- 一句话表达一个主要意思。复杂条件拆成步骤或列表。
- 同一对象使用同一名称。首次出现缩写时，按读者需要说明用途。
- 文件名、命令、配置项、环境变量和接口名使用行内代码。
- 链接文字说明目标内容，如“验证计划”，避免使用“这里”。

本项目统一使用以下术语：

| 术语 | 含义 |
| --- | --- |
| 宿主 Agent | 用户正常对话、使用可信接口、负责委派和审核的外层 Agent；默认 Codex，可选 Claude Code、OpenCode |
| 开发 Agent | 在隔离环境中调用指定中转站和模型、执行开发任务的内层 Agent；独立配置，默认 Codex |
| 委派控制层 | 准备工作区、启动运行时、管理任务和导出结果的宿主侧组件 |
| 原项目 | 用户在宿主机中的项目目录及其已有修改 |
| 独立工作区 | 与原项目分离的任务工作目录；文件提供方式待验证 |
| 交付结果 | 相对任务基线的修改、文件清单、日志和测试记录 |

## 标明实现与验证状态

优先记录当前实现和已验证的方法。尚未实现的需求、方案和计划，在开头标明状态。

| 状态 | 写法 |
| --- | --- |
| 已明确的需求 | 写清要求、范围与验收条件 |
| 方案建议 | 标为“草案”或“建议”，列出待验证项 |
| 外部资料声明 | 写明来源、整理日期和版本，说明是资料中的声明 |
| 代码观察 | 链接到固定提交，写清检查范围 |
| 推断 | 标明是适配判断，说明依据和验证方法 |
| 实测结果 | 记录版本、环境、命令、退出码、证据位置与剩余限制 |

使用明确日期和状态，避免用“本次”“目前可用”等依赖对话背景的表述。保留需求和用例编号，便于跟踪。引用原始需求时，说明摘记范围。

## 完成更新检查

1. 核对内容与实际文件、配置和验证记录是否一致。
2. 检查相对链接、文件名大小写、代码块和表格。
3. 更新 AGENTS.md 中的相关文档索引；入口变化时同步更新 README。
4. 文件结构变化时，更新[项目结构](structure.md)的中文文件树。
5. 确认公开文档未包含本机私有信息或真实凭据。
