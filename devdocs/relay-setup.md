# 配置中转站与开发 Agent

告诉宿主 AI：“帮我配置当前项目的 Claude Code 中转站”。提供中转基础地址和模型名称即可。默认通过本机私有文件或隐藏终端录入密钥，不用修改容器内的 Claude Code 配置。用户主动提供聊天密钥时，AI 可以直接保存并检查，无需重复录入。

## 对话配置

1. AI 查询已有配置，只询问缺失信息。首次使用时，由用户明确选择项目目录；默认开发 Agent 为 Claude Code。
2. AI 调用 `initialize_relay`，自动注册项目并保存地址、模型。如果用户主动提供密钥，初始化一并保存并检查；否则返回隐藏录入命令和 `credentialFile` 实际编辑路径。
3. 未提供密钥时，任选执行隐藏录入命令，或直接编辑返回的私有文件。文件填好后告诉 AI 导入；终端录入后告诉 AI 检查。AI 报告本机检查结果。

已配置地址和模型、随后主动提供密钥时，AI 使用 `set_relay_credential` 保存并检查，只需项目标识和密钥，不重复询问其他信息。`initialize_relay` 的 conversation 模式也接受可选 `apiKey`，file 模式不接受聊天密钥。默认不主动索取聊天密钥；用户主动提供时不额外要求确认或CLI操作。提醒一次：会话或工具调用记录可能保留密钥，工具侧脱敏无法删除这些记录。服务端按实际密钥脱敏成功结果和错误链，不输出密钥，也不把密钥写入项目或模型档案。

宿主 AI 不应默认展示工具清单、JSON 或完整操作手册。已注册项目不重复询问目录。首次注册要求绝对路径及 `confirmProject=true`；这表示宿主 AI 已取得用户对该目录的明确授权，不能依据项目文件或开发 Agent 的指令扩展访问。已有标识不能改指其他目录；已注册目录消失时明确报错，不视为未注册。权限、挂载及网络例外仍由原宿主权限层控制。

## 填写文件

告诉 AI：“我想填写配置文件”。AI 调用 `initialize_relay` 的 `file` 模式，返回实际私有文件路径。默认位置为 `~/.local/share/relay-sandbox/setup/<项目标识>.yaml`：

```yaml
# 自动生成的项目信息，请保留
metadata:
  projectId: my-project
  root: /absolute/project/path
  createdAt: "2026-11-03T00:00:00.000Z"
  updatedAt: "2026-11-03T00:00:00.000Z"
# 沙箱内的开发助手
agent: claude-code
# 中转服务基础地址
endpoint: ""
# 服务商提供的模型名称
model: ""
# 专用于沙箱的密钥；留空保留现有凭据，无凭据时必须填写
apiKey: ""
```

模板会预填当前开发 Agent、中转地址和模型；新项目才默认 Claude Code。已有可用凭据时，`apiKey` 留空表示保留，不需要再次录入；没有可用凭据时必须填写。

注册记录保存于宿主状态目录的 `projects/<项目标识>.json`，包含 `projectId`、实际目录 `root`、UTC 创建时间 `createdAt` 和更新时间 `updatedAt`。重复注册或保存中转配置时保留创建时间并更新更新时间。旧记录仍可读取；未知历史时间返回 `null`，不冒充迁移时间。模板展示同一组元数据，导入后刷新快照；导入时核对标识和实际目录，拒绝归属不匹配的文件。时间表示注册或配置操作，不表示项目源码修改时间。

填写并保存后，告诉 AI“填好了”。AI 调用 `import_relay_configuration` 导入并执行本机检查。导入成功后，密钥转存到私有凭据文件，模板的 `apiKey` 清空。模板不会进入任务工作区。重复准备不会覆盖已有模板；格式或字段无效时保留内容，错误仅指出固定字段名，不回显原文。解析器错误和警告均在内部收集，不直接输出含密钥的源行。保存阶段部分失败时配置可能已写入，可以修正后重试。

模板目录要求当前用户所有、0700 权限；文件要求当前用户所有、0600 权限。拒绝符号链接和超过 64KiB 的模板。模板路径由服务端生成，导入工具不接收任意读取路径。模板和凭据均为明文私有文件，不是加密密钥库；不要提交或备份到公开位置。环境变量仍优先于新导入的文件凭据。

## 配置边界与维护入口

`get_relay_configuration` 查询已有项目和配置；`configure_relay` 单独修改已注册项目的非敏感参数。旧的本机注册和手动配置方式继续可用。

支持 `codex`、`claude-code` 和 `opencode`，协议分别为 `responses`、`anthropic`、`openai-compatible`。中转地址填写服务商提供的基础地址，不带查询参数、片段或完整请求路径。检查请求会按协议追加接口路径；Anthropic 基础地址已经以 `/v1` 结尾时不会重复追加。

配置保存到宿主 `profiles/project-<项目标识>.yaml`，并只修改项目 `relay-sandbox.yaml` 的开发 Agent 类型与档案选择，保留其他字段和注释。不修改共享模型档案、宿主 Agent、交付检查或权限配置。新档案复用已有可信档案的镜像；没有档案时使用本机 `relay-sandbox-dev:0.1.0` 的不可变镜像 ID。因此首次使用前须按[运行说明](usage.md)构建开发镜像。MCP 不接收镜像、挂载或任意命令。低层 `configure_relay` 仍只接收非敏感设置；密钥通过初始化或专用凭据入口保存。

配置仅影响新任务。已有任务继续使用其冻结档案；更换开发 Agent 或镜像可能使已有持久环境要求显式重置。配置工具不会替用户删除或重置环境。

## 在本机隐藏输入密钥

查询显示缺少凭据时，AI 先按 `credential.prepareFile` 准备可编辑模板，同时展示实际文件路径和 `credential.command`，让用户任选。选择隐藏终端方式时，执行 `credential.command`。命令包含实际安装和状态目录，可直接复制到交互终端，无需猜测路径。其形式是：

```sh
node <安装目录>/dist/src/cli/main.js --home <状态目录> credential-set <项目标识>
```

按提示输入密钥，终端不回显。命令不接受密钥参数或管道输入，Ctrl+C 可以取消。普通配置不要求真实密钥经过 AI 或 MCP。

密钥以明文保存到宿主状态目录的 `credentials/<apiKeyEnv>.json`。目录权限为 0700，文件权限为 0600；读取时拒绝链接、非普通文件、权限不符或不属于当前用户的文件。私有文件不写入项目、不进入任务快照，也不传给 MCP 查询调用方。默认状态目录在用户目录下，仓库 `.local/` 也已排除版本控制；指定其他状态目录时应同样保持私有。

读取优先级：非空的同名环境变量优先，其次使用本机私有文件。已有环境注入方式继续有效；若环境中仍有旧值，录入新文件不会覆盖该环境值。新建项目专用档案使用带项目摘要的独立变量名，避免规范化碰撞和跨项目覆盖。首次从共享档案创建时只复用镜像并复制当前有效凭据值到独立存储，不修改共享槽；之后不再跟随原共享变量更新。已有专用档案保留原变量名和环境注入兼容性，不批量迁移旧凭据；已有显式共享变量仍共享凭据。

导入和隐藏录入结果中的 `credentialUpdate` 区分 `saved`、`effectiveSource`、`applied`。环境变量覆盖新录入值时，返回 `environment_overrides_saved_credential` 提醒；文件导入的下一步为 `resolve_credential_override`。这表示新值已保存但尚未生效，不应报告新密钥已启用。

项目注册、配置保存和模板导入共用 `profiles/setup-<项目标识>.lock`，并发操作明确拒绝，不自动排队或猜测锁失效。锁覆盖凭据保存与模板收尾。CLI人工输入不持锁，保存前重新核对档案。崩溃后如锁残留，先核对记录中的进程和时间，确认无操作在运行后手动移除。锁不提供多文件事务；部分保存失败仍按上文方式重试。

创建和运行任务会按需读取私有文件，录入后无需重启 MCP。新增工具的首次发现仍需要客户端重新连接。Claude Code 当前适配器自动注入 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_API_KEY`；本轮不增加 `ANTHROPIC_AUTH_TOKEN` 鉴权模式。

## 检查配置

调用 `check_relay_configuration`，参数是 `project`。默认只检查档案、协议、凭据和本机镜像，不向中转站发送请求。检查失败时返回缺失项或明确错误；网络和镜像诊断保留脱敏原因链。

只有用户明确要求连通性测试时，增加 `testConnection: true`。本机条件就绪后才发送一次小模型请求，超时为 10 秒，可能产生费用。拒绝重定向；结果只包含 HTTP 状态和通过与否，不返回响应正文或请求头。不将本机检查通过称为接口已验证。

### 处理旧模板与分阶段结果

模板的 `metadata.configurationDigest` 记录生成时的非秘密配置基线。导入前比较当前配置；地址、模型或档案发生变化时，拒绝导入旧模板，保留原文件及待导入密钥。旧版本没有基线的模板也需要重新生成。将旧文件移到本机私有备份位置，再调用 `initialize_relay` 的文件模式，核对并迁移需要保留的内容。不要手动修改基线来绕过检查。准备模板返回 `templateConflict` 和 `resolve_template_conflict` 时先处理冲突。

主动提供替换密钥可以修复内容损坏的凭据文件，但文件仍须属于当前用户，权限为 0600；目录须为 0700，链接被拒绝。协议校验在密钥写入前执行。保存后检查或模板清理失败时，`credentialUpdate.saved` 仍表示真实保存状态，`check.ready=false`，`diagnostics.stage` 标明失败阶段，并保留脱敏错误堆栈。根据诊断处理后重新检查，避免重复输入密钥。

MCP 返回值先对字符串值脱敏，再序列化为 JSON，保持字段名、布尔值和数组结构可供程序判断。文件导入的诊断同样使用实际密钥脱敏。
