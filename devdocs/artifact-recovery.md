# 重试收集已完成的产物

AI 已完成、任务却在收集阶段失败时，先读取 `get_task`。当 `nextAction=collect_artifacts` 时，调用 MCP `collect_artifacts`，再用 `wait_task` 等待。CLI 可执行：

```sh
node dist/src/cli/main.js collect <任务ID>
```

此入口只重新收集原工作区，不启动开发 Agent、不请求模型，也不增加轮次。成功后进入 `checking`，再执行正常的交付检查与审核。不要先清理任务或重置环境，否则可能失去待收集文件。

新任务通过 `failureStage=collection` 标记收集失败。旧任务仅对明确的“不支持的归档类型”错误提供兼容重试。执行失败、已清理任务、准备未完成或持久环境已被其他任务借用时拒绝操作。任务锁冲突返回等待建议；遗留锁仍按监督与恢复规则处理，不自动抢占。

## 硬链接的导出规则

Docker tar 中的 `link` 表示硬链接。导出器先验证全部条目，再解析硬链接目标，支持前向引用与链接链。目标必须最终指向本次归档内的普通文件；绝对路径、越界路径、缺失目标、链接循环和符号链接目标均拒绝。

每个合法硬链接在宿主导出为独立普通文件，不保留共享 inode。修改一份产物不会同时改动另一份。沿用单文件 256 MiB 限制、禁止重复条目及禁止穿过链接祖先的规则。普通符号链接仍保留链接本身，不读取其指向的宿主内容。

错误记录包含条目路径、类型、链接目标及原因链。失败会关闭归档流，保留容器文件；重试会重建宿主结果目录，并清除旧清单、摘要和审核状态，避免使用不完整结果。设备文件、FIFO 等特殊类型继续拒绝，不静默忽略。

## 限制导出展开总量

Docker 导出默认最多 8 GiB、200,000 个非根条目。目录、普通文件和链接都计入条目数量；普通文件正文和每个硬链接展开副本都计入累计字节数。硬链接目标解析和全部副本预算检查完成后才开始复制。超限明确失败，不静默漏掉文件；调整容量或减少待导出文件后重试收集。

```yaml
resources:
  maxExportBytes: 8589934592
  maxExportEntries: 200000
```

预算作用于任务结果和持久环境同步中的 Docker 导出。每次导出独立计数，不是宿主磁盘配额，也不替代单文件 256 MiB 限制。旧任务未保存这些字段时使用相同默认值；已有任务使用创建时保存的配置，新任务读取项目配置。

## 重新准备当前候选

开始新一轮开发时即废止旧结果摘要及代次绑定，包括派发后尚未启动的窗口和凭据检查失败的情况。每次收集产生新的 `resultGeneration`。收集先废止旧候选绑定、审核和检查，并移除 `candidate/`、`current/` 与旧交付计划。结果查询只展示已经准备且摘要匹配的交付计划。

准备交付完成候选构建后写入 `candidateGeneration`。确认候选要求它与当前收集代次一致；缺少绑定的旧任务需要重新准备交付。人工解决冲突可以修改当前代次的候选，然后确认，不必重新运行开发 Agent。不能通过确认旧候选绕过新结果的准备流程。
